# description 写法指南

description 是 L1 唯一线索，决定 Skill 能否在几十上百个候选里被选中。

## 公式

```
[做什么] + [何时用] + [触发词 / 文件类型 / 反向触发]
```

## 对照示例

| 场景 | 差 | 好 |
|---|---|---|
| 数据分析 | 帮你处理数据 | 分析 CSV/Excel 并生成透视表、图表与统计摘要。Use when 用户上传表格、要求做数据统计或可视化时。 |
| 代码评审 | Review 代码 | 对代码或 diff 做分级评审，输出阻塞/建议/可选问题清单。Use when 用户要求 review、审查 PR、检查这段代码时。 |
| 文档写作 | 写文档 | 按给定大纲撰写技术文档，含术语表与示例代码。Use when 用户要写 README、接口文档、设计方案时。 |

## 反向触发（防止误触发）

当某个 Skill 容易被过度触发时，显式写清边界：

```
不要用于简单的格式调整；那种情况直接用编辑器替换即可。
```

## 自检三问

1. 用户会用什么措辞提出这个需求？—— 写进去。
2. 哪些文件类型 / 关键词出现时应该用？—— 写进去。
3. 什么时候**不该**用？—— 写进去（可选）。
