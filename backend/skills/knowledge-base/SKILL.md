# 知识库检索与管理

用户的私有资料（内部文档、手册、规范、产品资料）存放在**知识库**中。
本技能规定：何时调用检索、如何调用、如何引用作答，以及维护类操作的流程。

## 一、先判断：要不要检索

| 判定 | 动作 |
| --- | --- |
| 私有事实、内部规定、手册章节、产品参数、编号/单号 lookup | **调用** `knowledge_base_search` |
| 用户明确说「查知识库」「按文档」「根据资料」 | **调用** |
| 闲聊、通用常识、纯推理、代码生成、数学 | **不调用** |
| 知识库中没有该主题 → 检索一次为空后 | **不重复硬试**，如实告知（见第三节） |

> 原则：**凡是有可能存在于私有资料的答案，先查再答**；不要凭记忆代替检索，
> 也不要在不需要私有事实的问题上浪费检索。

## 二、调用规范

工具：`knowledge_base_search`

| 参数 | 用法 |
| --- | --- |
| `query`（必填） | 检索友好的核心问句——去掉「请问 / 帮我 / 我想知道」等口语填充，保留实体与术语 |
| `knowledge_base_ids` | 用户指定了库才传；未指定则省略（工具内会按提问自动路由到最相关的库） |
| `retrieval_mode` | 通常省略（跟随各库默认，推荐已配好为 hybrid）；明确需要精确术语匹配时用 `keyword`，语义改写问题用 `semantic` |
| `top_k` | 默认 5；结果都差时不盲目加大，先换措辞重试一次 |

- **复合问题拆开多次调用**：如「A 的流程是什么？B 的时限呢？」拆成两次，每次一个子问题
  （工具内部也会做一次提问分析，但拆开比一次塞长句更准）。
- **换措辞重试最多一次**：同义改写后仍无结果，就按「未找到」处理，不要反复换词硬试。

## 三、作答规范（硬性）

1. **必须标注来源**：每条来自知识库的结论后注明「来源：文档名」；多条来源分别标注。
2. **检索为空必须拒答**：明确回答「知识库中未找到相关信息」，**禁止编造**；
   可建议换个说法再试，或提示该资料可能尚未入库。
3. **不混淆来源**：只把检索到的内容当作知识库依据；确需补充常识时，单独说明
   「以下不属于知识库内容」。
4. **提示位翻译成大白话**：结果头部的 `missing_vector_index` 表示该库尚未建立向量索引
   （当前是关键词检索）；对用户用一句人话说明即可，不要贴英文代码。
5. **低相关/片段截断**：`truncated` 表示该分段被截断、内容可能不完整，必要时说明依据有限。

### 输出样例

```text
按《运维值班手册》，管理员密码可在设置页重置，重置后需要重新登录。

来源：运维值班手册.md（位置 2）
```

## 四、维护操作（建库 / 上传 / 重建 / 模型）

维护类请求（“把这份资料存进知识库”“重建一下索引”“加一个嵌入模型”）有两种通道：

1. **引导到管理页（优先）**：`/knowledge`（会话页右上角「工具箱 → 📚 知识库」）——
   可视化完成建库、上传（可选分段策略）、重建索引、模型配置，最直观、可确认。
2. **REST API（用户要求由你直接操作，或环境没有界面时）**：端点的完整清单与示例
   见 `references/management-api.md`（按需读取）。

注意事项：
- 上传前**先确认目标知识库**（列出现有库让用户选；只有一个库时可默认它）。
- 大文档解析较慢（几秒到几十秒），告知用户正在处理即可。
- **换嵌入模型后必须重建向量**（管理页或 API 上的「重建」），否则语义检索不可用。
- 上传音频（mp3/wav 等）需要服务端已配置 ASR 端点（`HARNESS_KB_ASR_ENDPOINT`）；
  未配置时报错信息可直接转述给用户，并给出配置方法。
- 删除知识库 / 文档属于不可恢复操作：**先向用户复述将删除的对象与影响，确认后再执行**。

## 五、常见追问

- 「为什么搜不到？」→ 依次排查：换关键词（专有名词/编号更有效）→ 确认资料是否已上传
  → 确认查的是正确的库。
- 「语义检索为什么用不了？」→ 该库未绑定嵌入模型或未重建向量；给出配置与重建步骤。
- 「能不能搜多个库？」→ 可以：不传 `knowledge_base_ids` 时跨全部库检索并按提问路由；
  指定多个 id 时只查这些库。
