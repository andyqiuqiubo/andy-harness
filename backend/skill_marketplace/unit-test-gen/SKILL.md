# 单元测试生成

基于现有代码生成**贴近项目风格**的单元测试：先识别被测单元的依赖与边界，再补齐正常、边界、异常三类用例，而不是堆砌无意义的断言。

## 何时使用
- 用户给出函数/类/文件，要求补充或新建测试。
- 用户希望提升覆盖率、或为新功能补测试。
- 重构前后需要一套可回归的测试。

## 步骤
1. **看项目约定**：先找仓库里已有的测试文件，确认框架（pytest / jest / vitest 等）、目录位置、命名与断言风格，**沿用**而非另起炉灶。
2. **识别边界**：列出被测单元的输入空间——正常值、空值、None/undefined、极值、超长字符串、类型不符。
3. **分类用例**：
   - 正常路径：典型输入 → 期望输出（含关键返回值/副作用）。
   - 边界：最小/最大、空集合、单元素。
   - 异常：非法输入应抛出的具体异常类型；依赖失败时应有的降级。
4. **可运行优先**：每个用例独立、无顺序依赖；用 fixtures/mocks 隔离外部依赖（网络、数据库、时间）。
5. **产出**：给出可直接落盘的测试文件片段，并标注还需补充的用例。

## 注意事项
- 不要为了覆盖率写「永远为真」的断言（如 `assert result is not None` 后无实质检查）。
- 测试应验证**行为契约**，而非实现细节，减少重构时的脆性。
- 若被测代码耦合严重、难以测试，先指出可重构点，再给测试。
