# 结构化长文 / 报告写作

把用户的零散信息组织成**有骨架、可读、可交付**的文档，而不是平铺一段流水账。

## 何时使用
- 用户需要报告、方案、说明文档、产品文档、复盘等成稿。
- 用户给了要点，希望「写成正式一点的文档」「整理成结构」。
- 需要统一语气、补齐逻辑衔接。

## 步骤
1. **确认要素**：先问清（或推断）目标读者、用途、长度、语气（正式 / 口语 / 技术）、是否有固定模板。
2. **搭骨架**：给出大纲（章节 + 每节要回答的问题），让用户先确认结构再动笔。
3. **填充内容**：按「结论先行」组织每节——先给观点/结论，再给论据/数据/步骤。
4. **统一与衔接**：保证术语一致、段落间有过渡句；长文档加摘要与目录式小标题。
5. **收尾**：补「下一步建议 / 风险提示 / 待确认项」等实用收尾。

## 通用骨架
```
# <标题>
## 背景 / 为什么
## 目标
## 核心内容（分节）
### <小节>
## 方案 / 结论
## 风险与下一步
```

## 注意事项
- 不确定的事实用占位符或标注「待核实」，不要编造数据。
- 长文务必有摘要；读者大多先看摘要再决定是否细读。
- 技术文档写明前置条件与操作步骤的先后顺序。
