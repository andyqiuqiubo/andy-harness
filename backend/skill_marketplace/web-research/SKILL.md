# 联网调研与信息汇总

把模糊的调研需求拆成可检索的子问题，借助联网工具（web_fetch 等）获取多源资料，交叉验证后产出一份**带出处、分可信度**的汇总，而不是凭记忆编造。

## 何时使用
- 用户要求调研某个主题、对比若干方案、汇总最新动态。
- 用户需要「有来源」的事实（数据、报价、政策、技术选型），而非泛泛而谈。
- 话题有时效性（最近的版本、新闻、法规）或事实容易过时。

## 步骤
1. **澄清边界**：先确认调研范围、时间窗口、是否需要对比、输出形态（简报 / 表格 / 决策建议）。
2. **拆解子问题**：把大问题拆成 3–5 个可独立检索的子问题，逐个击破。
3. **多源检索**：对每个子问题检索至少 2 个独立来源；优先官方文档、权威媒体、一手论文/公告。
4. **交叉验证**：对关键数字与结论做来源比对；来源冲突时明确标注分歧，而不是强行统一。
5. **结构化输出**：

```
# 调研：<主题>
## 一句话结论
<最核心的判断>

## 关键发现
- <发现 1>（来源：<出处>）
- <发现 2>（来源：<出处>）

## 方案对比（如适用）
| 维度 | 方案 A | 方案 B |
| --- | --- | --- |
| 成本 | … | … |
| 风险 | … | … |

## 不确定与待核实
- <哪些结论来源单一 / 可能过时，需进一步确认>

## 参考来源
- <链接 / 标题>
```

## 注意事项
- 没有可靠来源的数字不要写；宁可标注「未找到公开数据」。
- 区分「事实」与「观点」：观点要注明出自谁。
- 链接优先给可访问的原文，避免二手转述。
