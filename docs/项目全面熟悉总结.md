## 1. 项目定位（一句话）

**andy-harness** 是一个「插件化 Agent Harness（智能体底座）」：Python FastAPI 后端 + Vue 3 前端，提供对话 GUI、多模型接入、工具调用与 human-in-the-loop 权限门控、MCP 客户端、技能/插件市场、长期记忆、定时任务、子代理与多 Agent 编排、轨迹追踪、Computer Use 桌面操控等能力。**一切皆插件，内核零业务逻辑**，对齐 Claude Code / Codex / Cline 等主流 Agent 的最佳实践，面向开发者学习与二次开发。

- 当前版本 v1.0.0（开发者预览版）；在 Windows 10 个人 PC 开发，深度联调的模型仅 DeepSeek `deepseek-v4-flash`。
- 两条铁律：① Computer Use（操控整个本机桌面）是默认单人本机定位；② 正在向「团队/企业私有化多用户平台」演进（见 `docs/EPIC-multiuser-asset-permission.md`，尚未实施，仅设计）。

## 3. 运行形态与启动

| 形态 | 启动方式 | 端口 | 数据目录 |
|---|---|---|---|
| 浏览器模式（主） | 双击 `start-all.bat`（或 `make backend` + `make frontend`） | 后端 8000，前端 Vite 5173 | `backend/data/` |
| 桌面壳模式 | 装好 Rust 后双击 `start-desktop.bat` | 动态选空闲端口 | `%APPDATA%/andy-harness`（与浏览器模式数据隔离，属设计如此） |
| Docker | `docker compose up -d` | 8000 | 挂载卷 |

- 前端访问必须用 `http://localhost:5173`（Vite 默认只绑 localhost，Windows 解析为 IPv6；`127.0.0.1` 连不上）。
- 后端只监听 `127.0.0.1`；CORS 默认放行 Vite 5173 与 Tauri 自定义协议源，可用 `HARNESS_ALLOWED_ORIGINS` 追加（`backend/harness/main.py:278`）。
- 环境要求：Python 3.11+、Node 22.12+（Vite 8 engines）、pnpm 10、uv；Rust 仅桌面壳需要。
- 首次安装：`cd backend && uv sync --extra dev`（54 包，实测 16 分钟）→ `cd frontend && pnpm install`（253 包，2 分钟）→ `pnpm build`（**后端 pytest 与桌面壳都依赖 frontend/dist，未构建时 pytest 有 1 例失败**）。
- 代理：飞书 CLI（Go 子进程）只认 `HTTPS_PROXY` 环境变量；后端启动时自动读取 `backend/.env.local`（gitignore）注入并保证 `NO_PROXY=localhost,127.0.0.1`（`main.py:65-115`、Makefile:5-8）。

## 4. 后端架构（backend/harness/）

### 4.1 总体：微内核 + 插件

四层结构（详见 `01-architecture.md`）：

```
kernel（内核：ServiceRegistry / EventBus / HookManager / PluginLoader，零业务逻辑）
   ↑ 插件 activate() 时注册回来
engine（Agent 引擎：agent_loop / tool_registry / runtime / checkpoint）
modules（17 个业务模块实现：session / context / memory / permission / mcp / scheduler ...）
api（FastAPI 装配层：18 个 REST router + 1 个 WS /ws/chat + /api/health）
infra（SQLite Database / Repository / crypto / security）
```

**启动装配**（`backend/harness/main.py`，只做装配不含业务）：
1. `lifespan`（main.py:210）→ 补 `USERPROFILE/HOME` 环境（供 lark-cli）→ 注入代理 → `_init_components()`（main.py:154：注册内核组件、Database、Auth、Session/Context/Provider 服务，内置 calculator/current_time 工具，从 DB 加载自定义 provider）；
2. `PluginLoader.load_and_activate_all(backend/plugins)`（main.py:224）加载全部插件——每个插件在 `activate(ctx)` 里把服务/工具/钩子注册回内核；
3. 中间件：`AuthMiddleware`（先加、在内层）+ CORS；统一错误格式 `{code,message,detail,trace_id}`（api/errors.py）；
4. 挂载 18 个 REST router（main.py:308-325）+ WS（main.py:328）+ `/api/health`。
5. 关闭时停用非 core 插件并关 DB。

**插件契约**（kernel/）：`plugin.json` 清单（id/name/version/type/entry/core_api）→ 五种类型 `provider/tool/service/hook/channel`（contracts/base.py:14）；`PluginContext` 注入受限门面（events/services/hooks/PluginStorage/SecretStore）；deactivate 时按 owner 自动清理注册项；core 插件禁止停用。

### 4.3 WebSocket `/ws/chat`（api/ws/chat.py，流式对话主通道）

- 帧：上行 `{session_id, content, provider_id, model, temperature, system_prompt, attachments}`、`stop`、`confirm_reply`；下行 `token_delta`（含 reasoning_content）、`tool_event`、`context_snapshot`、`confirm_request/confirm_timeout`、`attachment_warning`、`error`、`done`（带 usage）、`stop_ack`。
- 认证：握手 `?token=`（chat.py:232）；会话归属校验（chat.py:411）。
- 单 reader 架构（chat.py:331）：唯一 `_reader()` 分发到 message/control 两个队列，消除双 receive 竞争。
- `_StreamingProviderProxy`（chat.py:54）：每连接代理，把模型流式 chunk 直推前端 + EventBus 旁路广播；靠 contextvar 识别子代理会话，子代理输出不混入主界面。
- 人工确认：`_request_confirm`（chat.py:270）发 `confirm_request` 用 Future 等 `confirm_reply`，120s 超时按拒绝。
- 循环收尾：发最终 `context_snapshot`、首问自动生成 ≤20 字标题、`done` 帧。

### 4.4 Agent 引擎（engine/agent_loop.py，核心中的核心）

`AgentLoop.run()`（agent_loop.py:138-354）——每次对话的执行骨架：

1. 设 `AgentRuntime` 到 ContextVar（runtime.py，供 task 等工具按异步任务读取 provider/model）；
2. 持久化用户消息（重新回答模式复用原 user 消息）；
3. `while iterations < max_tool_iterations`（默认 10）：
   - `_build_context`（:422）：pre 钩子 → `ContextService.build`（策略压缩 + 多模态渲染）→ 前缀系统提示（自定义 system_prompt → 当前时间 → 语言 → **Skill L1 目录** → **MCP 能力清单** → 长期记忆 hint）→ post 钩子；
   - `_call_model`（:682）：工具定义取自 ToolRegistry（OpenAI function-calling 格式）→ pre 钩子 → **SSE 流式**调用 + 指数退避重试 3 次 → 按 index 合并分片 tool_calls → post 钩子；
   - 无 tool_calls → 终答跳出；有则持久化 assistant(tool_calls) 后执行 `_execute_tool_calls`（:822）；
4. 每个工具调用：pre 钩子 → **权限裁决** `PermissionService.decide`（:519）→ 审计落库 → deny 回填错误 tool 消息（保证 API 不 422）/ confirm 走人工确认回调 → `tool.execute()`（needs_session/needs_user 自动注入）→ post 钩子 → `tool_event` 实时推送 → 回填 tool 消息（带 tool_call_id）；
5. 终止：无 tool_calls / `stop()` 置位 / 达到迭代上限（**撞上限后强制一次"无工具"收尾调用** :266，避免悬空工具结果）；
6. 持久化终答（含思维链 reasoning）；异常时 `_cleanup_failed_round`（:1000）删孤立消息。
7. 检查点：`_checkpoint`（:381）每轮写 `agent_runs` 表；`checkpoint.resume_run`（engine/checkpoint.py:109）支持 REST 触发续跑。span 全程发 EventBus `trace.span` 由 tracing 落库。

### 4.5 LLM Provider 层（modules/model_manager/）

- `OpenAICompatibleProvider`（openai_compatible.py）：**OpenAI 兼容协议**，httpx 直连 `{base_url}/chat/completions`，SSE 流式（含 usage），401 不重试；tiktoken 估算 token；`GET /models` 做健康检查。
- `ProviderRegistry`：按 provider_id 单例缓存；API Key 用 Fernet 加密（infra/crypto.py，密钥从 Windows 注册表 MachineGuid 派生，不落盘）；内置三家 Provider 插件 deepseek/qwen/doubao（仅声明 base_url + 默认模型），自定义 provider 走 REST 创建（`custom_` 前缀动态子类）。
- 实际联调充分的只有 DeepSeek；Qwen/Doubao 未充分验证（README 明示）。

### 4.7 infra 与数据模型

- **SQLite**（stdlib sqlite3）：默认 `backend/data/harness.db`（`HARNESS_DB_PATH` 可覆盖）；单共享连接 + RLock、WAL、busy_timeout=5000。**15 张表**：sessions、messages、attachments、context_snapshots、providers、todos、artifacts、memories（含 embedding 列）、spans、scheduled_tasks(+runs)、agent_runs、channel_links、users、permission_audit（新增）。
- **schema 自升级**：`Database.init_schema()`（infra/database.py:299）全部 `CREATE TABLE IF NOT EXISTS` + `PRAGMA table_info` 检缺失列后 `ALTER TABLE ADD COLUMN`——旧库打开即自动补列，**无需迁移脚本**。
- **Repository 层**（infra/repository.py）：数据模型与仓储抽象，"保留切换 Postgres 的能力"；模块服务一律经 Repository 访问 DB。
- **零依赖安全原语**（infra/security.py）：PBKDF2-HMAC-SHA256（200k 迭代）、HMAC 自签名 token。
- 配置无集中服务：环境变量（HARNESS_*）+ 各模块状态 JSON（data/settings.json、permission.json、skill_state.json、memory_state.json 等）+ mcp.json + DB providers 表。

### 4.8 工具系统与权限门控（human-in-the-loop + 审计）

- **工具清单**（risk 分级 read/write/dangerous）：内置 `calculator`/`current_time`；插件 `web_search`/`web_fetch`（read）、`code_runner`（**dangerous**，走 sandbox_manager，支持 Docker 容器隔离：一次性容器、禁网、资源限制）、`computer_use`（**dangerous**，桌面操控，自带独立授权 REST）、`task`/`parallel`/`pipeline`（子代理与编排）、`todo_write`、`memory_save`/`memory_search`、`use_skill`、`read_artifact`、`theme_switcher`、`ip_lookup`、`jev_choice/noul/score`（结构化决策）、`integration_*`（智连器）；外加 MCP 动态工具（查询前缀判 read，其余保守 write）。
- **门控链**：`PermissionService.decide`（modules/permission_manager/service.py:154）——风险取 `tool.risk_level`（未注册工具按 dangerous 最保守）；单工具覆盖 > 全局策略（auto / **confirm_dangerous 默认** / confirm_write / confirm_all）；状态存 data/permission.json。deny → 不执行回填错误；confirm → WS `confirm_request` 等人裁决。
- **审计**（modules/permission_manager/audit.py，新增未提交）：只在真实执行路径两处落库——stage=decision（策略裁决）与 stage=resolved（人类裁决，decided_by=human）→ `permission_audit` 表；**不放** `decide()` 内以免前端渲染污染审计。
- 降级：PermissionService 未注册/异常时放行但记 error 日志（agent_loop.py:531）。

### 4.9 插件 / 技能 / MCP 生态

- `backend/plugins/` **35 个插件目录**（实测启动加载 34 个）：10 个 core 服务插件 + channel_manager/jev_manager 等 + 3 个 Provider + 1 个 Telegram channel + 18 个工具插件 + integration_hub（新增）。
- 插件市场 `backend/marketplace/`（6 包：元气宠物、文件管理器等）→ `/api/plugins/marketplace` 一键安装；技能市场 `skill_marketplace/`（10 包）→ `/api/skills/marketplace`；MCP 市场 `mcp_marketplace/`（10 个免鉴权服务）→ 写入 mcp.json 并重连。当前 mcp.json 配了 libgen/deepwiki/fetch。
- 插件与技能均支持 **zip / git 外部分发安装**（`install-external`，防路径穿越）。

### 4.10 飞书 / CLI 入站（integration_hub 插件）

飞书 provider 三种模式（plugins/integration_hub/feishu_provider.py）：
1. **cli（出方向主路径）**：官方 Go CLI `lark-cli` 子进程覆盖消息/云文档/多维表格/日历；二进制定位顺序：状态文件 → `HARNESS_FEISHU_CLI_PATH` → 已知位置 `F:\tools\larkcli\...` → PATH。**必须给它 HTTPS_PROXY 环境变量**（见 §3）。
2. **channel（入方向）**：lark-oapi SDK WebSocket 长连接（免公网回调），群聊 @机器人 → 直接驱动完整 AgentLoop → 应用身份回群；SDK 同步回调 3s 限制 → 只解析过滤后投递后台协程；专用 event loop 独立线程。
3. **api（兜底）**：手搓 tenant_access_token 调少量接口。

另有通用 Webhook 渠道（REST `POST /api/channels/inbound/{name}`）与 Telegram 渠道（`HARNESS_TELEGRAM_BOT_TOKEN`）。`harness/cli/chat.py` 是独立验证脚本，不属于 FastAPI 应用。

## 5. 前端架构（frontend/）

### 5.1 技术栈与构建

Vue 3.5 + TypeScript 6 + Vite 8 + Pinia 4 + Vue Router 4 + markdown-it + highlight.js + `@tauri-apps/api`（同一份代码跑浏览器与 Tauri）。vite dev 代理：`/api`→8000、`/ws`→8000(ws)。测试 vitest + jsdom（9 文件 43 用例）。构建 `vue-tsc -b && vite build`；主包约 1.3MB **未做路由级代码分割**（已知债务）。

### 5.2 路由与视图

路由仅 3 条：`/`（HomeView）、`/chat`（ChatView）、`/settings`（SettingsView）；插件可动态增删路由。**无路由级登录守卫**——认证门在 `App.vue` 组件层（见 §5.6）。

- **ChatView.vue**（1906 行）：主聊天界面。WS 消息注册、人工确认弹窗、待办面板、附件选择与客户端校验、追问/删整轮/fork/重新回答；核心 computed `displayItems` 把消息流归并为「答案气泡 + 过程折叠框」——一组中间 assistant/tool 消息折叠进 `ProcessStep[]` 由 ProcessTrace 展示。
- **SettingsView.vue**（4773 行，最大文件）：11 个 tab——providers / session / memory / plugins（内嵌 IntegrationsPanel 智连器）/ skills（技能市场）/ mcp（含 MCP 市场）/ schedule / security（权限）/ audit（内嵌 AuditLogView）/ artifacts / general（5 套主题 + 中英文）。
- **HomeView.vue**：品牌落地页，MatrixRain 数字雨 + 3D 视差标题 + WisdomTree 生成式分形树。
- 其余组件：SessionSidebar（搜索 300ms 防抖/日期分组/右键菜单/导入导出）、MessageItem（双布局气泡、token 用量、附件 blob 渲染）、MarkdownRenderer（markdown-it + hljs）、ProcessTrace（执行过程折叠框，live 展开/终答收缩）、IntegrationsPanel（飞书等智连器连接/调用/渠道启停）、AuditLogView（审计过滤+分页）、ModelSelector、PluginOverlayHost（插件悬浮层宿主）等。

### 5.3 状态管理（9 个 Pinia store）

`chat`（最核心：WS 帧消费 `handleWSFrame`、流式状态、附件暂存、done 后用真实 UUID 对账、切会话时序守卫 selectSeq）、`auth`、`settings`（主题/语言/会话参数，与 /api/settings 双向同步）、`providers`、`plugins`、`plugin-loader`（前端 UI 插件运行态）、`skills`、`todos`、`permissions`。

### 5.4 API / WS 客户端

- `src/api/client.ts` 单例：统一 `request<T>()` 拼 `apiBase()`、注入 Bearer、401 统一处理；`uploadAttachments` multipart；`fetchAttachmentBlobUrl` blob 取图。
- `src/api/runtime.ts`：浏览器用相对路径；Tauri `invoke('get_backend_url')` 取绝对地址；启动轮询 `/api/health`（500ms × 120s）等后端就绪。
- WS（client.ts 内 `apiClient.ws`）：单连接；`send()` 在 CONNECTING 时进 pendingQueue 补发；断线指数退避重连（1s→30s，10 次）；**无应用层心跳**；关闭码 1008 → token 失效回登录门。

### 5.5 i18n / 附件 / 渲染

- 附件：ChatView 客户端预校验（扩展名白名单/数量/大小）→ `POST /sessions/{id}/attachments` → 附件 id 随 WS 消息发送；服务端拒收下行 `attachment_warning` 黄条提示；历史图片用 blob: 渲染。
- Token 用量展示、思维链（reasoning_content）折叠展示、工具卡片完整参数与结果。

### 5.6 认证（E12）

`App.vue`：`showLogin = ready && enabled && !isAuthenticated` 时整站只渲染 LoginView。`authStore.init()` 在 main.ts 挂载前拉 `/auth/status`（默认关）与 `/auth/me`。开启后 HTTP 401 与 WS 1008 统一清 token 回门；审计 tab 额外要求 admin。

### 5.7 前端 UI 插件机制

## 6. 前后端关联：一条消息的完整旅程

```
用户在 ChatView 输入（可带附件 id）
  → WS /ws/chat?token= 上行帧（chatStore.sendMessage；CONNECTING 时进 pendingQueue）
  → 后端校验 token/会话归属/附件归属（api/ws/chat.py）
  → AgentLoop.run（engine/agent_loop.py:138）
      ├─ 持久化 user 消息（messages 表）
      ├─ ContextService.build 上下文（策略压缩+多模态渲染+Skill/MCP/记忆前缀）
      ├─ OpenAICompatibleProvider.chat SSE 流式
      │     └─ 每连接 _StreamingProviderProxy 直推 → WS token_delta → 前端流式渲染
      ├─ 有 tool_calls：权限 decide + 审计 →（confirm 则 WS 弹窗等 confirm_reply）
      │     → ToolRegistry.execute（MCP/code_runner/sandbox 各按其道）
      │     → tool_event 实时推送 → 前端 ProcessTrace 更新；todo_write 顺带刷新待办面板
      └─ 无 tool_calls：终答持久化（含 reasoning）→ checkpoint → spans
  → 后端发最终 context_snapshot、自动标题、done(usage)
  → 前端 reloadMessages 用后端真实 UUID 对账，清空流式缓冲
```

旁路入口走同一 AgentLoop：Webhook/Telegram/飞书渠道入站（channel_links 会话映射）、定时任务（隔离会话+受限工具集）、子代理（临时会话）。**这是理解全项目的最短路径：所有入口最终都收敛到 `AgentLoop.run()`。**
