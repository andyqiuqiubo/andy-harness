## 3. 逐项修复记录

### P0-1 录制回放会话 ID 路径穿越 → 任意目录删除（已实证）

**原问题**：`DELETE /api/desktop-repeat/sessions/{sid}` 的 `sid` 为裸 `str`，Starlette 路径正则 `[^/]+` 放行 `..`，服务层 `shutil.rmtree(self._root / sid)` 无根目录边界校验，PoC 实证可删除 `sessions_root` 之外的任意目录。同源读路径 `get_session`/`compile_session`/`vision_status` 也可越界读。

**修复位置**：
1. `backend/harness/infra/safe_path.py`（**新增**）：`is_safe_identifier()` 白名单、`safe_join()`（白名单 + `resolve()` + `is_relative_to()` 二次保险）、`safe_join_or_none()`、`UnsafePathError`。
2. `backend/harness/modules/desktop_repeat/service.py`：新增 `_session_dir(sid)` 守卫；`delete_session` 改用 `_session_dir()`，`shutil.rmtree(..., ignore_errors=True)` → `ignore_errors=False` + 显式 `except OSError` 记日志；读路径复用同一守卫（封堵 P1-5）。
3. `backend/harness/api/rest/desktop_repeat.py`：新增 `_check_sid(sid)`，覆盖 `stop_recording`/`get_session`/`delete_session`/`compile_session`/`vision_status` 等全部端点（REST 层纵深防御）。

**验证方式**：
- PoC 脚本重跑：`shutil.rmtree(root/'../victim')` 后 `victim dir still exists: True`。
- `tests/test_core_modules_security.py` 新增路径穿越回归用例（`DELETE /sessions/..`、`DELETE /sessions/../x` 断言 4xx 且目标目录完好），52 个安全用例全部通过。

**残留项**：无（P0-1 根源已封堵）。
**后续建议**：为 `desktop_repeat` 建 `tmp_path` 路径安全测试夹具，固定 `sessions_root` 与同级 `victim` 目录场景，防止回归（体检报告 §8.3 第 3 条）。

### P0-2 录制器子进程透传宿主机完整环境变量

**原问题**：`_spawn_recorder()` 传入 `{**dict(os.environ), ...}`，把后端进程全部环境变量（含模型 Provider API Key、数据库口令、代理凭据）交给子进程，直接违反 `AGENTS.md` 安全红线（“禁止在子进程中透传完整 `os.environ`”）。

**修复位置**：
1. `backend/harness/infra/subproc.py`（**新增/扩展**）：`build_env_allowlist()` 工具，显式白名单（`PATH`/`SYSTEMROOT`/`WINDIR`/`TEMP`/`TMP`/`USERPROFILE`/`APPDATA`/`LOCALAPPDATA`/`HOMEDRIVE`/`HOMEPATH`/`LANG`） + `HARNESS_REPEAT_*` 前缀 + 必填编码键。
2. `backend/harness/modules/desktop_repeat/service.py`：`_spawn_recorder` 改用 `build_env_allowlist()`，不再整体透传 `os.environ`。
3. `backend/harness/modules/reverse_engineering/stages.py`：java/javap/反编译器子进程接入 `build_env_allowlist()`。
4. `backend/harness/modules/reverse_engineering/rebuild.py`：子进程接入 `build_env_allowlist()`。

**验证方式**：
- `grep -n "os.environ" harness/modules/desktop_repeat/service.py` 不再出现整体透传；`reverse_engineering` 三处子进程 env 均走兜底白名单。
- `tests/test_core_modules_security.py` 新增 mock `Popen` 断言 `kwargs["env"]` 不含 `OPENAI_API_KEY`/`DASHSCOPE_API_KEY` 等敏感键，52 用例全过。

**残留项**：无（P0-2 根源已封堵，三套 env 标准统一为一套，顺带完成 P2-3）。
**后续建议**：新增 `assert_env_isolated(env)` 测试夹具，三处子进程共用（体检报告 §8.3 第 4 条）。

### P1-1 安全门默认策略对高风险动作免审

**原问题**：`RepeatConfig.approval_policy` 默认 `"never"`，非法配置值静默回落 `"never"`；`SafetyGate` 在 `never` 下对 `dangerous` 动作直接 `allow`；`risk_of` 未知动作默认 `"write"` 而非 `"dangerous"`，危险动作默认免审。

**修复位置**：
1. `backend/harness/modules/desktop_repeat/config.py`：`approval_policy` 默认 `"never"` → `"degraded"`；非法值回落 `"degraded"`（不再回落最宽松的 `never`，`never` 降级为需显式 opt-in）。
2. `backend/harness/modules/desktop_repeat/safety_gate.py`：`risk_of` 未知动作默认改为 `"dangerous"`；审批提供方返回待审但不带错误码时，按真实风险补发（`write`→`RP-4004`，`dangerous`→`RP-4003`），保证前端/审计码与风险等级一致。

**验证方式**：

### P1-2 知识库 DOCX 解析无解压炸弹防护

**原问题**：`parse_docx` 用 `zipfile.ZipFile` 后逐个 `zf.read(media_path)`，未对 `ZipInfo.file_size` 做总量/条目数上限；`zf.read()` 一次性把整个成员读入内存，几百 KB 构造 zip 可致服务端 OOM。PDF 解析 `zlib.decompress(raw)` 同构问题。

**修复位置**：`backend/harness/modules/knowledge_base/parsers.py`：DOCX 解析前统计 `sum(i.file_size for i in zf.infolist())` 与条目数，超阈值（100 MB / 万条）抛 `ParseError`；PDF `zlib.decompress` 追加输出上限校验。

**验证方式**：`tests/test_core_modules_security.py` 新增构造高压缩比 zip 断言抛 `ParseError` 的用例，52 用例全过。

**残留项**：无。
**后续建议**：阈值可通过配置项外置（默认 100 MB），避免误杀合法大文档。

### P1-3 逆向 jar 解包无解压量上限防护

**原问题**：`_extract_jars` 用 `zf.extractall(out_dir)`，无解压量上限，且 `except zipfile.BadZipFile: continue` 不捕获 `ValueError`（路径穿越），导致整个阶段 FAILED 而非降级。

**修复位置**：`backend/harness/modules/reverse_engineering/stages.py`：改用逐成员 `zf.open()` + 手动写盘，统计解压后总字节数并设上限；显式校验每个成员名 `Path(name).resolve().is_relative_to(out_dir.resolve())`；`except (zipfile.BadZipFile, ValueError, OSError)` 统一降级为 `continue` + 记日志。

**验证方式**：`tests/test_core_modules_security.py` 新增 jar 解包炸弹/越界成员用例，52 用例全过。

**残留项**：无。
**后续建议**：与 P1-2 共享同一解压上限常量，保持两处阈值一致。

### P1-4 知识库 Embedding/Rerank 端点未走 SSRF 校验

**原问题**：`httpx.AsyncClient().post(url, ...)` 中 `url = f"{self.endpoint}{path}"`，`endpoint` 由用户提交并存储，全程未调用 `net_guard.assert_url_safe`，可指向 `127.0.0.1` / `169.254.169.254` 构成 SSRF，且响应体会回显。

**修复位置**：
1. `backend/harness/modules/knowledge_base/embedding.py`：`EmbeddingClient` / `RerankClient` 构造时调用 `net_guard.assert_url_safe(endpoint)`。
2. `backend/harness/modules/knowledge_base/adapters.py`：ASR adapter 构造时接入 `assert_url_safe`。
3. `backend/harness/modules/desktop_repeat/vision/client.py`：视觉辅助端点同样接入 `assert_url_safe`（顺带封堵同类 SSRF）。

**验证方式**：`tests/test_core_modules_security.py` 新增 endpoint 指向 `127.0.0.1` / `169.254.169.254` 断言被拒绝的用例，52 用例全过。

**残留项**：无。
**后续建议**：对用户自建的内网端点提供显式 allowlist 开关，供内部私有化部署场景使用。

### P1-7 知识库 build_vectors 向量数量不匹配被静默吞掉

**修复位置**：

**验证方式**：`tests/test_core_modules_security.py` 新增 mock embed 返回短列表断言抛 `KBServiceError` 的用例，52 用例全过。

**残留项**：无。

### P1-9 录制回放 run 失败路径未保证释放输入设备租约

**原问题**：`lease.acquire()` 成功后，后台任务 `asyncio.create_task(self._run_and_persist(...))` 若 `runner.run()` 抛未捕获异常，无 `finally` 保证 `_release_lease()` 被调用，导致全局互斥锁 `Global\andy_repeat_input` 被永久占用，此后所有录制回放被 `RP-5004` 拒绝，只能重启后端。

**修复位置**：`backend/harness/modules/desktop_repeat/service.py`：`start_run` / `_run_and_persist` 用 `try/finally` 包裹 run 生命周期，`_release_lease()` 放入 `finally`；`_cleanup_run` 中一并调用（幂等守卫已有）。

**验证方式**：`tests/test_core_modules_security.py` 新增“run 内部异常后租约仍可再次 `lease.acquire()`”用例，52 用例全过。

**残留项**：无。
**后续建议**：为租约加“心跳超时自动释放”兜底，防止进程崩溃（非正常退出）导致锁永久悬挂。
