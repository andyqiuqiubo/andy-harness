## 1. 项目简介与适用场景

**andy-harness** 是一个**插件化 Agent Harness（智能体底座）**。它不是一个聊天机器人，而是一套把"让大模型稳定、安全、可观测地干活"工程化的框架：

- **插件化**：工具、技能、UI 扩展、接入渠道全部是插件，内核零业务逻辑；
- **可观测**：每次对话的模型调用与工具调用都落为 span 链（轨迹），能看到"哪里慢、哪里贵、哪里错"；
- **省 context**：工具超大输出自动落盘为「制品」，上下文只留摘要与引用；长期记忆按相关性注入；
- **可控**：工具按 只读 / 写操作 / 危险 分级，危险操作（如执行代码）默认弹窗要你点「允许」才运行；
- **可编排**：1.0.x 起提供 Dify 风格的可视化工作流画布、模板中心、洞察看板、评测实验室与插件开发者工作台。

**典型用法**：本机私有部署的 AI 助手底座、Agent 工程学习样本、插件/技能二次开发平台。
**默认部署形态**：单用户、本机访问，数据全部落在本机文件里，不依赖任何云服务。

## 2. 环境要求与安装启动

### 2.1 环境要求

| 组件 | 版本要求 | 说明 |
|---|---|---|
| 操作系统 | Windows 10（已验证） | macOS / Linux **尚未验证**，存在未知风险 |
| Python | 3.11+ | 后端 FastAPI |
| Node.js | **^20.19.0 或 >=22.12.0** | Vite 8 的硬性要求；Node 22.0~22.11 **不满足**，会启动失败 |
| 包管理器 | **pnpm**（必须） | 用 `npm install` 会导致锁文件不一致 |
| 浏览器 | Chrome / Edge 现代版本 | 访问 `http://localhost:5173` |
| 大模型 API Key | DeepSeek / Qwen / Doubao / 任意 OpenAI 兼容服务 | 深度调试过的模型是 DeepSeek `deepseek-v4-flash`；也可用 OortCloud 免费额度（见 [4.1](#41-第-1-步配置模型-provider)） |

### 2.2 三步启动（开发模式）

```bash
# ① 后端：创建虚拟环境并安装依赖
cd backend
python -m venv .venv
.venv/Scripts/python.exe -m pip install -e .        # Windows
# macOS/Linux 请用 .venv/bin/python -m pip install -e .

# ② 前端：安装依赖
cd frontend
pnpm install

# ③ 启动
# 方式 A：分别启动
cd backend  && .venv/Scripts/python.exe -m uvicorn harness.main:app --host 127.0.0.1 --port 8000
cd frontend && pnpm dev          # 默认 http://localhost:5173
# 方式 B（Windows 推荐）：仓库根目录一键启动
start-all.bat
```

> **访问地址必须用 `http://localhost:5173`**（前端 dev 绑定 IPv6，直连 `127.0.0.1` 可能不通）。
> 桌面壳（Tauri）用户直接双击安装包即可，无需上述步骤，详见 `desktop/README.md`。
> `start-all.bat` **不会自动安装依赖**，只复用已有的 `backend/.venv` 与 `frontend/node_modules`。

### 3.1 对话页（空态）

![对话页空态](manual/screenshots/02-chat-empty.png)

对话页分成三块：

| 区域 | 内容 |
|---|---|
| 左侧会话栏 | 新建 / 导入 / 清空、搜索框、按日期分组的会话列表 |
| 顶部标题栏 | 品牌名 + 当前会话标题；右侧是**模拟模式**开关、Provider 下拉、模型选择器、**工具箱**（洞察 / 评测 / 工作流 / 模板 / 开发者五个 1.0.x 功能入口）、连接状态徽章、设置齿轮（启用认证时还有「退出登录」） |
| 右侧主区 | 消息区 + 底部输入框 |

**连接状态徽章**有四种：`已连接` / `连接中...` / `重连中...` / `已断开`，对应 WebSocket 状态。若长时间「已断开」，说明后端未启动或端口被占（见第 12 节）。

### 3.2 对话页（有内容）

![对话页有内容](manual/screenshots/03-chat-conversation.png)

这张图展示了实际对话中的关键元素：

1. **AI 回答的工具调用过程框**（标题「执行过程」）：工具名、参数、结果逐条展开——这是「可观测性」的直接体现；
2. **Markdown 渲染**：代码块高亮、列表、加粗；流式输出实时渲染；
3. **每条回答下方的 token 用量**：`输入 X · 输出 Y · 合计 Z tokens`（含缓存命中/未命中）；
4. **思维链展示**：DeepSeek 推理模型的思考过程逐步展示，完成后自动折叠；
5. **底部输入框**：Enter 发送、Shift+Enter 换行；右侧 📎 添加附件、发送 / 停止生成按钮；内容超过 7 行时出现「放大输入框」；输入框下方常驻「内容由 AI 生成」合规标注条。

> 输入框**只支持点击 📎 选择文件**，不支持拖拽上传。

## 4. 第一次对话（从零到出结果）

### 4.1 第 1 步：配置模型 Provider

点顶部齿轮进入设置页，默认落在「模型」标签：

![模型](manual/screenshots/04-settings-providers.png)

**方式一：自有 API Key**

1. 点 **+ 新增**，填写四项：
   - **名称**：自定义，如 `DeepSeek`
   - **Base URL**：如 `https://api.deepseek.com/v1`
   - **API Key**：密码框，填你申请的密钥
   - **模型列表**：逗号分隔，如 `deepseek-chat,deepseek-reasoner`
2. 点 **添加** 保存；
3. 回到列表点 **测试连接** → 显示 `✓ 连通` 或 `✗ 失败`；
4. 状态开关切到 **已启用**。

**方式二：不花一分钱（OortCloud 免费额度）**

配置表单下方有一张常驻的 OortCloud 推广卡片（未领取时才显示）。点 **免费领取** → 跳转 OortCloud 统一登录页授权 → 后端自动领取平台下发的 **10 元免费模型额度**（免费 NewAPI 令牌）并自动创建 `custom_oortcloud` Provider，回到会话里即可直接选用免费模型。**无需自有 API Key、无需付费**，足够把全部功能完整试一遍。领取流程带 state 防重放，令牌密钥本地加密存储。

**方式三：内置 LLM 网关的免费通道（需本机登录态）**

会话页 Provider 列表里已内置 **Cline / OpenCode / WorkBuddy / Qoder CN** 四个「（免费）」厂商，选中即可对话。它们复用**本机已登录的客户端登录态**（Cline CLI / Magpie），无需填写 API Key；前置条件、可用性检测与常见提示见 **§9.8**。

要点：

- 行内有 `🔑 已配置` / `⚠ 未配置密钥` 徽章；**未配置密钥时不能启用 / 测试 / 停用**；
- **编辑**时 API Key 留空表示「不修改」；
- **删除**只对自定义 Provider（`custom_` 前缀）可用，且已配置密钥且启用时置灰；
- Qwen / Doubao 内置插件**不支持**环境变量回退，请在设置页填写。

### 4.2 第 2 步：设置默认模型与温度

切到「会话」标签：

![会话设置](manual/screenshots/05-settings-session.png)

- **默认模型**：新会话使用的模型名（占位提示 `deepseek-flash`）；
- **温度 (Temperature)**：0–2 滑块，步进 0.1，实时显示数值，越高越发散；
- **系统提示词**：多行文本，作为该会话的系统指令；
- 改完点 **保存设置**（提示「设置已保存」）。

### 4.3 第 3 步：发消息

回到对话页，在输入框输入内容，**Enter 发送**（Shift+Enter 换行）。流式生成时输入框禁用，点 **停止生成** 可中断——中断后已生成的部分会完整保留为一条助手消息，并打上「用户已停止回答」标注；若中断时仅有思考链、尚无正文，思考过程会以可折叠块展示（见 [6](#6-消息操作复制--重答--追问--分叉--删除)）。

**没有 API Key 也能体验**：点顶部 **模拟模式** 开关（按钮变为「模拟中」），此时不消耗任何 token、不需要密钥，系统会用模拟回复演示完整交互流程。

### 4.4 附带文件（文档 / 图片）

点输入框 📎（title：`添加附件（文档 / 图片）`）选择文件：

| 限制项 | 数值 |
|---|---|
| 单次总文件数 | ≤ 8 |
| 文档 | ≤ 5 个，单个 ≤ 200KB（txt/md/csv/json/py/js/ts 等 26 种） |
| 图片 | ≤ 4 个，单个 ≤ 1.5MB（png/jpg/gif/webp/bmp，自动缩放控 token） |

文档内联为文本、图片按 OpenAI 视觉规范以 base64 注入模型。选错类型会提示「包含不支持的文件类型，已忽略」。已选附件以 chip 展示，可点 × 移除。删除会话会连带清理附件文件。

### 4.5 危险工具的人工确认弹窗

当 AI 要执行危险工具（如代码执行）时，会弹出确认框：标题「**AI 请求执行工具**」，展示**工具 / 原因 / 参数(JSON)**，底部两个按钮：**拒绝** / **允许执行**。超时未响应按**拒绝**处理。

策略可在「设置 → 安全」标签调整（见 [7.9](#79-安全工具权限与人工确认)）。

## 6. 消息操作（复制 / 重答 / 追问 / 分叉 / 删除）

把鼠标**悬浮**到消息上即可看到操作按钮：

**用户消息**
- **复制提问**：复制后提示「复制成功」3 秒；
- **删除本轮问答**：物理删除该提问及其回答（不可撤销）。

**助手消息**（有正文时）
- **复制回答**；
- **重新回答**：原位删除该轮并用原问题重新生成；
- **针对该回答继续追问**：进入追问模式，输入框上方出现引用条（显示「追问中」+ 原问题摘要，可「取消追问」）；
- **从此处分叉出新会话**：把该消息之前的历史复制为新会话。

每条助手回答下方还显示 **本次用量**（输入 / 缓存 / 未命中 / 输出 / 合计 tokens）。被「停止生成」中断的回答带「用户已停止回答」标注，位于内容下方；仅有思考链被中断时，思考过程以可折叠块渲染。

## 7. 设置页十一大标签详解

设置页顶部是一排标签，左右两侧有滚动箭头（标签多于一屏时）：`模型` / `会话` / `记忆` / `插件` / `Skills` / `MCP` / `定时任务` / `安全` / `审计` / `制品` / `通用`。左上角有「← 返回对话」。

> **与旧版的变化**：原「轨迹」标签已并入「审计」作为其子视图；「工具权限与人工确认」从「通用」拆分为独立的「安全」标签；「插件」标签内新增「智连器 / 赋能器」两个子页签。

### 7.1 模型（Providers）

![模型](manual/screenshots/04-settings-providers.png)

新增 / 编辑 / 测试连接 / 启用·停用 / 删除，详见 [4.1](#41-第-1-步配置模型-provider)。OortCloud 免费额度领取入口也在本页（见 4.1「方式二」）。

### 7.2 会话

![会话](manual/screenshots/05-settings-session.png)

默认模型 / 温度 / 系统提示词，详见 [4.2](#42-第-2-步设置默认模型与温度)。

### 7.3 插件（智连器 / 赋能器）

![插件-智连器](manual/screenshots/07-settings-plugins-connectors.png)

「插件」标签内部分为两个子页签：

**智连器（默认）** —— 接入第三方系统：

- **飞书**：三种模式任选——`api`（填 app_id / app_secret 直调开放接口）、`cli`（lark-cli 子进程）、`channel`（WebSocket 长连，群里 @机器人即答，需可选依赖 `lark-oapi`：`uv sync --extra feishu`）；
- **OortCloud**：免费模型额度领取入口（与「模型」标签的推广卡片同一能力）。

**赋能器** —— 本机能力插件：

![插件-赋能器](manual/screenshots/08-settings-plugins-local.png)

- **已装插件列表**：每行有 **启用/停用开关**（核心插件 `core` 锁定不可关，显示「核心」徽章）、**配置**（齿轮，按 schema 渲染表单，点「保存配置」）、**卸载**（仅市场来源插件，确认「此操作将删除插件文件，不可撤销。」）、权限标签与版本徽章；
- **从插件市场安装插件**：展开「插件市场」面板 → 每张卡片点 **说明** 看详情弹窗 → 点 **安装**（确认「确定从插件市场安装『名称』吗？」）→ 装好后卡片显示「已安装」徽章；
- 市场里还有**前后端联动**类插件（如元气宠物：后端启用后，会话页出现可走动、可喂食的悬浮宠物）；
- 从 UI 安装 / 停用插件即时生效，不需要重启后端。

### 7.4 Skills（技能）

![Skills](manual/screenshots/09-settings-skills.png)

- 每行可 **启用/停用**（停用后不再进入模型视野），带来源徽章（内置 / 用户级 / 插件自带）、版本、正文字符数、资源数、`allowed_tools`；
- **查看详情**（眼睛图标）：弹出 SKILL.md 正文与随附资源列表——这就是"三级渐进式披露"：目录常驻、命中才加载正文、脚本与参考文档按需读取；
- **重新扫描**：重新扫描技能目录；
- **技能市场**：与插件市场共用面板，可一键安装 / 重装 SKILL.md 技能包。

### 7.5 MCP（接入外部工具生态）

![MCP](manual/screenshots/10-settings-mcp.png)

- **添加并连接**：
  - **本地进程 (stdio)**：名称、启动命令、参数（空格分隔）；
  - **远程服务 (SSE)**：名称、服务地址（SSE）、请求头（每行 `Key: Value`，可选）、描述（可选）；
- 列表项显示连接状态点（绿=已连 / 灰=未连）、类型徽章、命令或 URL、**工具 chips**（该 server 提供了哪些工具）；
- **重连** / **移除**（确认「确定移除该 MCP server (名称)」）；
- **MCP 市场**：与插件市场共用面板，可一键接入 libgen / deepwiki / context7 / cloudflare-docs / gitmcp 等免鉴权公开服务。

> 客户端同时兼容**旧版 SSE**（GET 建流）与 **streamable-http**（POST 直连），远端只支持其中一种时会自动适配。

**本地 vendored 服务：REA 逆向工程（`mcp_servers/rea`，含原生反编译）**

仓库内置了源码方式集成的 REA（Reverse Engineer Anything v6.4.0，MIT）MCP 服务，让 AI
在不看源码的前提下分析本地二进制与应用，结论附证据与局限，分析全程在本机执行。
**原生反编译已启用**：项目内隔离安装 Ghidra 12.1.4 + JDK 21（工作区 `.tools/`，不依赖
系统全局安装），可对原生 PE（x86/x64 的 exe/dll）输出**反编译伪代码**、汇编、函数清单、
字符串、调用关系与交叉引用；另有 JS/Electron、PE 资源、.NET 等引擎无关的静态分析。

- **构建**（干净克隆后执行一次）：`cd mcp_servers/rea && npm ci && npm run compile && npm run artifacts:skills`（要求 Node >= 22.19）；原生反编译另需按 [mcp_servers/README.md](../mcp_servers/README.md) 6.5 节准备 `.tools/` 内的 Ghidra/JDK；
- **注册**：`backend/mcp.json` 中的 `rea` 条目默认启用（本机为绝对路径，env 已含 Ghidra 配置；示例配置 `mcp.example.json` 用相对路径），重启后端或在「设置 → MCP」重连即生效；
- **三个 per-server 选项**（本机配置已使用，默认关闭不影响其它 server）：
  - `max_line_bytes`——REA 的 `tools/list` 单帧约 2 MB（170 个工具），超过 stdio 默认 1 MB 行上限，须调大为 16 MB，否则表现为"连接假死"；
  - `tool_allowlist`——工具白名单，本机收敛为 23 个工具（7 个静态分析 + 16 个 Ghidra 原生反编译族；全量 170 个工具注入会显著占用模型上下文）；
  - `request_timeout`——单请求超时 600 秒：Ghidra 冷启动（导入 + 自动分析）提供方截止即 330 秒，默认 60 秒会误杀长任务；
- **原生分析流程**：`open_binary`（导入目标，冷启动约 1~2 分钟）→ 函数/字符串清单检索 → `procedure_pseudo_code`（伪代码）/ `procedure_assembly`（汇编）→ 调用图与交叉引用；JVM 堆上限 `GHIDRA_HEADLESS_MAXMEM=3G` 控制内存占用；
- **完整说明与验证记录**见 [mcp_servers/README.md](../mcp_servers/README.md)。

### 9.6 Browser Use 浏览器自动化（BrowserSkill）

> 让 AI **像人一样操作你已登录的 Chrome / Edge**：填表、点击、翻页、抓取、截图、借用/归还标签页。网页类需求会自动走这条路，不需要你指定工具。

**它是怎么工作的**

- 内置 [腾讯开源 BrowserSkill](https://github.com/Tencent/BrowserSkill) **v0.3.3**（MIT）官方技能包，位于 `backend/skills/browser-skill/`，来源、校验与本地改动记录在同级 `VENDOR.md`。
- 三件套版本需一致：**bsk CLI v0.3.3 + 浏览器扩展 v0.3.3 + 技能 v0.3.3**（通信协议 1.3）。
- 守护进程由后端自动托管：内置插件 `browser_daemon` 负责探测并在需要时拉起 `bsk daemon`（日志 `logs/browser-daemon.log`）。**你不需要打开终端执行任何 bsk 命令**——这是设计约束，不是可选项。

**第一次使用（只需做一次）**

1. **bsk CLI**：按官方 install 命令安装 v0.3.3（技能正文有命令与直链）。
2. **浏览器扩展**：扩展商店在中国大陆通常不可达，此时用官方离线包：已代下载并校验的 `ext-v0.3.3` 位于 `D:\browser-skill-extension\v0.3.3`。在 Chrome 打开 `chrome://extensions` → 打开「开发者模式」→「加载已解压的扩展程序」→ 粘贴上述路径。Edge 同理。
3. **技能**：已内置，设置 → Skills 里可查看/启停。

**日常用法**：直接在对话里说「打开 example.com 总结页面」「抓取某后台最近 10 条数据整理成表格」。已登录状态会被复用（无需重新登录），会话窗口**默认置顶显示**（`--focus`），你能直接看到操作过程。

**几个要知道的边界**

- 借标签页、验证码、登录等涉及人工的环节会明确请你确认/接管，不会擅自操作。
- `chrome://` 开头的页面、扩展安装页**无法被自动化**（浏览器安全限制），只能手动。
- 单次任务的模型调用预算已提高到 25 轮；搜索类需求直接给结果页 URL（如 `www.baidu.com/s?wd=关键词`）能显著更快完成。
- 若抓图失败但文字正常，多半是扩展版本低于 0.3.3，按第 2 步升级即可。

### 9.7 操作录制回放（andy-repeat）

> 把「在电脑上演示一遍」录成**可编辑、可复用、零 token 回放**的流程。核心是**录事件流而非录像素**：录制时取证每个点击落点的控件语义，回放时按定位链确定性地还原，**主路径不调用大模型、断网也能跑**。

**五步工作流**（入口：更多功能 → 操作录制回放，即 `/repeat`）

| 步骤 | 做什么 | 关键点 |
|---|---|---|
| ① 录制 | 点「开始录制」，把流程完整演示一遍 | 输入密码/敏感窗口会自动暂停或脱敏 |
| ② 解析 | 停止后自动解析为结构化步骤 | 每步带定位链与置信度，`needs_review` 的需人工确认 |
| ③ 发布 | 发布为工作流，可在画布上编辑 | 与 Workflow Studio 同一画布，`gui` 节点可增删改 |
| ④ 干跑 | 零副作用体检：只解析定位、不注入 | 先看这一步能过，再真跑 |
| ⑤ 回放 | 真执行，实时进度走 SSE | 支持断点续跑、人工裁决、紧急停止 `Ctrl+Alt+.` |

**安全与隐私**：敏感窗口自动暂停、密码框内容永不记录（回放时转人工输入）、越界窗口与危险动作硬拦截。

**鲁棒性（近期修复）**：应用内弹出的**模态对话框**（如「另存为」）会被自动接管并继续回放，不会把回放锁死；弹窗标题与录制时不一致时，以窗口 class 精确命中作为强证据放行；新窗口/对话框弹出慢会等待其出现（默认 2.5 秒）；`hotkey` 步骤定位链耗尽时自动降级为焦点注入（例如"输完网址按回车后页面才跳转"这类因果倒置场景），无需重新录制。

**可选：视觉辅助核对**（`repeat.vision_enabled`，默认关）— 解析完成后异步调用视觉理解模型（默认百炼 `qwen3-vl-plus`）逐步比对前后帧，回答「这一步做了什么 / 画面是否变化 / 是否生效」，产出疑似未生效清单，供人工复核。纯旁路，失败不影响录制与回放。

**详细操作**（含全部热键、错误码速查、CLI 用法）见 [`docs/manual/andy-repeat-录屏回放用户操作手册.md`](manual/andy-repeat-录屏回放用户操作手册.md)。

| 设置页自定义 Provider | 想接入任意 OpenAI 客户端 | 设置 → 模型 → 新增：`base_url=http://127.0.0.1:8000/v1`，API Key 填 `backend/data/gateway.bootstrap-key` |
| 管理台 | 管通道 / Key / 租户 / 用量 / 审计 | 会话页工具箱 →「LLM 网关」（`/gateway`） |

**主线：官方免费额度（一个 Key 即用，不依赖任何客户端）**

- **Qwen 百炼**：`set DASHSCOPE_API_KEY=sk-...` 后重启后端，模型列表即出现 `qwen-plus` / `qwen-max` / `qwen-flash` / `qwen3-coder-plus`（新用户每模型 100 万 tokens、共约 7000 万、90 天；模型名以百炼控制台为准）。
- **豆包方舟**：`set ARK_API_KEY=...` 后重启后端。方舟多数模型需先在控制台创建**推理接入点**，把 `backend/data/gateway.json` 里 `doubao-ark` 的 `models` 换成你的 `ep-xxx` 接入点 ID。
- 也可以完全不走网关：设置页新建自定义 Provider，填上面的 base_url + Key 即可。

**可选增强：客户端免费通道的前置条件**

| 通道 | 怎么登录 | 默认 |
|---|---|---|
| Qoder CN | 管理台「登录」→ 浏览器完成 Qoder 官方授权（PKCE 设备授权，**无需安装任何客户端**） | 关闭 |
| WorkBuddy | 自建登录框架已就绪、流程移植中；过渡期可借 Magpie 登录态 | 关闭 |
| Cline | 安装并登录 **Cline CLI**（OAuth 自建登录后续按同一框架扩展） | 关闭 |
| OpenCode Zen Free | **无需登录**，但 2026-10-23 起上游把免费档收归 OpenCode 客户端（第三方调用一律 403），默认禁用 | 禁用 |

> 凭据是**每位使用者自己的**：Qoder CN 的 token 由网关用本机 machine key 派生密钥加密后存在本地 `gw_credentials` 表，明文不落日志、不出仓库；仓库也不携带任何凭据。启用某通道后若未登录，该通道**不会**出现在模型列表（避免"选得到却报错"）；登录/配好 Key 后无需重启即自动出现。

**Qoder CN 自建登录步骤**：会话页工具箱 →「LLM 网关」→ 通道页 → Qoder CN 卡片点「登录」→「打开授权页」在浏览器用你的 Qoder 账号授权 → 网关每 2 秒轮询，成功后模型立即出现在会话页。卡片显示"当前借用 Magpie 登录态"时，点一次「登录」即可转为网关自存，随后 Magpie 可卸载。

**可用性检测**：系统定期探测各模型（真实流量冷却 + 免费目录核对，均不消耗额度），不可用的模型在下拉中实时标注并禁用，恢复后自动更新；检测结果以后端为唯一事实源，前端只镜像，避免状态不一致。

**常见提示**

- `Qoder 模型排队中，约 30s 后可重试`：上游免费档排队（错误码 10605），等 30 秒重试即可，**不会**把账号标记为不可用；

- `未找到 XXX 登录态`：对应客户端未登录，按上表准备后重启后端；
- `/v1` 返回 503：网关未启动或配置损坏，检查 `backend/data/gateway.json` 与后端日志。

**一键自检**：在项目根目录运行 `python tools/check_gateway.py`，会打印官方 Key 与四个客户端通道的登录态、后端注册的 `gw-*` Provider 与模型可用数（只读，不输出任何密钥）。

## 10. 认证与多用户

**默认关闭**：不加任何环境变量时是本机单用户模式，行为零变化，不需要登录。

**开启方式**：

```bash
# 后端启动时加环境变量
HARNESS_AUTH=1 .venv/Scripts/python.exe -m uvicorn harness.main:app --host 127.0.0.1 --port 8000
```

启动后：

- `/api/**` 强制 Bearer token（PBKDF2 口令哈希 + HMAC 签名，默认有效期 12h）；
- 会话与长期记忆按 `user_id` 隔离；WebSocket 支持 `?token=` 握手，无效则关闭（1008）；
- 前端**自动出现登录页**，任意页面未认证都会被锁定到登录门；401 或 WS 1008 时自动回到登录页；
- **状态变更类端点需管理员身份**：插件 / 技能 / MCP 的安装卸载、权限模式与系统设置写入等写操作，服务端统一经 `require_admin` 校验管理员身份，普通用户仅可调只读接口；单用户默认关闭认证时不受此限制（行为零变化）。

![登录页](manual/screenshots/24-login.png)

**初始管理员**：开启认证但没预设密码时，后端会在启动日志里生成初始管理员账号与随机口令，形如：

```
已启用认证但未提供管理员密码，已生成初始管理员 'admin' / xxxxxxxx（请立即登录并修改），也可用 HARNESS_AUTH_ADMIN_PASSWORD 预设
```

建议用 `HARNESS_AUTH_ADMIN_PASSWORD=<你的强口令>` 预设，首次登录后立即修改。
登录成功后，对话页右上角出现 **退出登录** 按钮。

> **当前限制**：多用户目前只提供「登录门」。用户 / 权限的**创建与管理暂无界面入口**，需调用 REST API（`GET/POST /api/users`、`DELETE /api/users/{id}`，需管理员身份）。

## 12. 常见问题排查

| 现象 | 原因与处理 |
|---|---|
| 前端打不开 | 必须用 `http://localhost:5173`，不要用 `127.0.0.1` |
| Node 版本明明够却起不来 | Vite 8 要求 `^20.19.0` 或 `>=22.12.0`；Node 22.0~22.11 会被卡，升级即可 |
| 没装依赖就启动，报「系统找不到指定的路径」/ 缺模块 | 先执行第 2.2 节的 ①②两步 |
| `make install` 报 command not found（Windows） | Windows 无 make，按 2.2 手动执行 |
| 提示必须用 pnpm | 不要 `npm install` |
| 能启动但没法对话 | 说明 Provider 未配 API Key，先做 [4.1](#41-第-1-步配置模型-provider)，或领 OortCloud 免费额度 |
| 端口被占用（8000 / 5173） | 换端口或结束占用进程；桌面壳与 `start-all.bat` 不要同时跑 |
| 连接状态一直「已断开」 | 后端未启动 / 端口不对，检查 8000 是否在监听 |
| 制品 / 记忆页提示「服务未启用」 | 对应插件（`artifact_store` / `memory_manager`）未激活，去「插件 → 赋能器」启用 |
| 开启认证后历史图片全部裂图 | 已修复：图片改用 fetch + blob 渲染（可带 Bearer），若仍异常请确认已重启后端与前端 |
| Computer Use 提示「桌面不可用」 | 未装 `desktop` extra：`uv sync --extra desktop` |
| 飞书 channel 模式连不上 | 未装 `feishu` extra：`uv sync --extra feishu`（提供 `lark-oapi`） |
| 桌面壳报缺 `cargo` / Rust 工具链 | 见 `desktop/README.md` 或改用 Web 模式 |
