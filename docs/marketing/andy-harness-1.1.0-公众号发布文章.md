上个月有朋友问我：你这项目，跟直接用 ChatBot 有什么区别？我张口结舌，半天憋出一句"它能让 AI 干活"。他追问，能让 AI 干什么活？我没答上来。

回来想了几天，决定用 1.1.0 这个版本正式回答。我们从 AI 落地的真实卡点里挑了三件最硬的：**查你自己公司里的资料、拆一个你不认识的程序、每天重复点鼠标的活。** 分别对应三个功能：知识库、工程强逆向、操作录制回放。

结论先说：三件事都做完了，全部开源，MIT 协议。下面是每个功能是什么、怎么做的、在哪能用，以及——更重要的是——哪些地方还不行。

## 一、知识库：先让 AI 知道你公司的事

大模型什么都会一点，但有两样不会：你们公司的退款政策，和你团队上周定的接口规范。不是它笨，是它真没见过。

常见的土办法，是把文档直接贴进对话框。问题很实际：一份手册贴一次，几千 token 就没了；聊到后面上下文一压缩，最先被忘掉的恰好是它。更尴尬的是贴多了它会"串味"——把 A 产品的参数安到 B 产品头上。

所以 1.1.0 做了知识库。思路不新鲜，上传、分段、索引、检索，但每个环节都按"本机跑、可降级、不丢数据"的标准做：

- **分段策略自动匹配**：带标题的 Markdown 按结构切，FAQ 按问答对切，长报告做父子分段（用小块检索、返回大块上下文），纯文本按规则切。上传时可以手动覆盖。
- **三种检索模式**：keyword（FTS5 + BM25，中文 bigram 分词）、semantic（向量余弦）、hybrid（RRF 融合）。没配嵌入模型也能用；缺向量索引时自动降级并说明原因；空库返回空列表，不报错。
- **音频和图片直接入库**：mp3 / wav / m4a 走内置 AudioAdapter 转写（OpenAI 兼容 ASR，配好端点即用）；文档里的图片抽成独立资产，有 OCR / VLM 描述就参与索引，没有也不丢分段。
- **最后是技能化**：检索封装成 `knowledge_base_search` 工具，模型自己判断该不该调。我们给它立了条规矩：知识库里没有的，必须明说"未找到"，不许编。

实际用起来是这样：上传一份运维手册，问"如何重置管理员密码"，它会先去检索，拿回三段相关内容，答案末尾标注来源——哪份文档、哪个位置。这套链路有 55 项测试兜底。管理界面在 `/knowledge`，会话页工具箱可以直接进；想让它按 SOP 来，设置页「技能」里还有配套的 `knowledge-base` 技能包，检索、引用、拒答的规范都写在里面，可启停。

## 二、工程强逆向：给你一个 exe，先别急着双击

每个人收到陌生 exe 时的抉择都一样：跑，还是不跑。1.1.0 想给第三条路——先让 AI 拆开看看。

「工程强逆向」是一条七阶段流水线：

**REA 静态逆向 → Java class 反编译 → Frida 动态插桩 → Firecracker 沙箱执行 → PentAGI 自动化分析 → 功能等价 exe 重建 → Evidence v2 证据固化。**

阶段之间不传文件，传结构化事实（facts）。比如静态阶段发现的字符串，会作为动态阶段运行时内存扫描的特征——静态说"这里有个可疑字符串"，动态去内存里验证它到底出现没有，形成交叉验证。

【配图：七阶段流水线示意图。主题：各阶段能力、输入输出与 facts 流转关系。意图：一图讲清"静态—动态"如何交叉验证、证据如何收口。来源：需按 pipeline 实际结构绘制，建议 1080×608】

最直观的一次验证，是对着 2.4 MB 的 Process Explorer（微软签名、带 GUI）：Ghidra 原生反编译跑了 275 秒，产出 3,628 个函数、3,556 条字符串，每个函数都有可读的 C 伪代码。17 KB 的 find.exe 这种小工具则是秒级出结果。

但更有意思的是倒数第二阶段——**功能等价重建**。流水线跑完，会按样本的能力特征自动选一种 UI 形态，用项目内隔离的 TCC 编译出一个新的原生 exe。四个样本实测自动选型：

- Process Explorer（2.4 MB）→ 进程管理器形态，18,944 字节，真枚举进程；
- 7-Zip 安装程序（1.36 MB）→ 安装向导形态，复刻原版对话框，Install 时真实解压出 106 个文件；
- find.exe（17 KB）→ 字符串浏览器，14,848 字节；
- 自生成的 1.5 KB PE → 纯事实兜底形态，8,704 字节。

新 exe 可以再丢回流水线反编译，"逆向 → 重建 → 再逆向"的闭环成立。

【配图：重建产物对比。主题：左为原版 Process Explorer 界面，右为重建 exe 的进程管理器界面。意图：用视觉对比证明"功能等价重建"不是 PPT。来源：需实拍双界面拼图，建议 1080×608】

最后一阶段是 Evidence v2 证据固化：所有产物进哈希链，每条证据的链哈希是 sha256(prev|seq|stage|kind|payload_sha256)，任一环被改，后续全断，随时可以离线校验。

【配图：Evidence v2 证据包。主题：evidence.md 报告头部（链头哈希、证据条数、分析对象）与证据链表。意图：展示"可离线校验的防篡改"具体长什么样。来源：可用 rev_eng/runs/<run_id>/evidence.md 实拍，建议 900×506】

要诚实地说：Firecracker 需要 KVM，PentAGI 需要 Docker，本机不满足时自动降级为本地等价执行，界面里会写清降级原因——换到有条件的机器上，不改代码，真引擎自动启用。入口在「更多功能 → 工程强逆向」，也可以不启动后端，一条 CLI 直接跑。

## 三、操作录制回放：把"每天点一遍"变成"回放一遍"

第三个功能来自一个很朴素的观察：很多人的工作，是每天在 ERP 里筛数据、点导出、改文件名，十年如一日。

让 AI 干这活，通常有两条路，都不太好。Computer Use 让模型看屏幕点坐标——每轮截图都是图像 token，账单看得心惊，界面一改版就点歪。传统按键精灵——死记坐标，窗口一挪就废。

andy-repeat 想两边的都要：**录事件流，不录像素。**

录的时候，全局钩子捕获鼠标键盘和窗口切换；每次点击除了坐标，还会记下落点的控件语义（控件类型、名称、AutomationId、结构路径等六类定位符）。停止后经一条九阶段确定性编译管线，归并成带定位链与置信度的结构化步骤，黄色卡片标出低置信步骤，可以拉到工作流画布里继续改。回放时按「UIA → 图像锚点 → 相对位置 → 坐标」逐环降级解算——控件还在，就按控件找；界面小改版，图像锚点兜底。整条主路径**零 AI、零 token、断网可用**，AI 只在三个可选环节出场（步骤语义命名、视觉辅助核对、失效修复建议），默认全是关的。

安全是照着"真敢交给它跑"的标准做的：

- 密码框内容永不落盘，敏感窗口自动暂停录制，敏感输入回放时转人工；
- 发布前先干跑体检：每步只解析定位、零注入，确认还能跑对再放真回放；
- 回放中检测到你真实移动鼠标，自动挂起等你处理；紧急停止热键 `Ctrl+Alt+.`；
- 危险动作与越界窗口硬拦截，不会"闭眼乱点"。

一次真机验证的实录：录"点输入框 → 键入 QA-123 → 点 Submit"，共 15 个事件，停止时 SHA256 清单封版，回放状态 SUCCEEDED，每步定位来源是 uia/focus。真机脚本 29 项检查（主流程 10、控制流 10、热键 9）全部通过，配套单测 169 项。

用起来是这种感觉：把流程完整演示一遍，起名、解析、干跑、发布，之后在对话里直接说"跑一下我录的每日导出流程"，AI 调 `repeat_run` 执行，日期、文件名还能传参覆盖。嫌每天说一句也麻烦？挂到定时任务里，按计划自己跑。

## 写在最后

三件事看起来不搭界，底层是同一个念头：AI 要干活，得先有资料室（知识库）、放大镜（逆向）、和一双不会累的手（录制回放）——而且每一件都得可控、可验、可回放。

质量上，后端全量测试 1,350 项通过、5 项跳过、0 失败，mypy --strict 全过；上面三个功能各有专项测试（知识库 55 项、录制回放 169 项加真机 29 项检查）。CI 两个 job 常绿。

andy-harness 仍是开发者预览版，全部代码开源，数据留在你自己机器上。接下来你可以：

1. **直接跑起来**：clone 仓库，配一个 DeepSeek Key（或领 OortCloud 免费额度，一分钱不用花），双击 `start-all.bat`；
2. **先看再装**：用户手册图文并茂，三个功能都有逐步说明；
3. **动手改**：内核几千行，照抄 `tool_calculator` 写你的第一个插件。

仓库地址：https://github.com/andyqiuqiubo/andy-harness

最后提醒一句：录制回放和 Computer Use 会真的动你的鼠标键盘，跑之前请读一遍 `DISCLAIMER.md`，理解权限分级和风险边界，再放手让它干活。

有问题、有想法，GitHub Issue 见。我一个人维护，但每条都会看。
