## 1. 文档目的与范围

### 1.1 目的

本方案描述一个面向私有知识沉淀与检索的知识库系统。系统以「文档摄取 → 分段清洗 → 向量/全文索引 → 检索 → 大模型技能调用」为主线，支持文本、图文混排、音视频及特殊格式文件的统一管理与语义化问答。

本方案直接参照 Dify 知识库的能力边界（Dataset / Document / Segment / 经济型与高质量索引 / 通用与父子分段 / 关键字·语义·混合检索 / Rerank），并在以下方面给出**明确的工程约束**：

- 分阶段存储的落地路径与格式约定；
- 4 种可自动匹配的分段与清洗方案；
- 自定义 Embedding 模型的可配置项与校验规则；
- 三种检索模式的定义、融合策略与降级行为；
- 将「提问分析 + 知识库检索」封装为可被大模型自主调用的 Skill。

### 1.2 设计原则

| 原则 | 说明 |
| --- | --- |
| 自洽一致 | 全篇使用统一的术语（见第 2 节），同一概念不混用多种叫法。 |
| 边界清晰 | 每个核心功能均标注「支持 / 不支持 / 预期行为」，避免实现歧义。 |
| 可分阶段交付 | 存储、检索、技能化按 Phase 1 / Phase 2 拆分，互不阻塞。 |
| 可观测可回滚 | 摄取与检索过程全链路留痕，分段可重建、索引可重建。 |
| 默认安全 | 检索 Skill 仅读不写，不触达外部网络，不替代模型作答。 |

### 1.3 阶段划分总览

| 阶段 | 存储内容 | 状态 |
| --- | --- | --- |
| **Phase 1** | 文本文档、图文混排文档 | 本方案核心交付范围 |
| **Phase 2** | 音频、视频、需特定应用打开的特殊格式文件 | 架构预留，本方案定义接口与适配器规范 |

### 1.4 文档阅读约定

- 「**必须（MUST）**」表示硬性约束，实现须满足。
- 「**应该（SHOULD）**」表示推荐约束，存在合理例外时可偏离并说明。
- 「**预期行为**」描述系统在给定输入下的确定输出，作为验收依据。

## 2. 术语表与一致性约定

为避免歧义，全文统一使用下表术语，不在同一含义下混用近义词。

| 术语 | 英文 | 定义 | 易混淆别名（禁止使用） |
| --- | --- | --- | --- |
| 知识库 | Knowledge Base (KB) | 一个独立的文档集合与索引单元，对应 Dify 的 Dataset | 数据集（仅在引用 Dify 时保留） |
| 文档 | Document | 用户上传的单个文件或一条外部记录 | 文件、素材（仅在泛指时可用） |
| 分段 | Segment | 文档经清洗后产生的最小检索单元（chunk） | 切片、块、片段（混用易歧义，统一用「分段」） |
| 父子分段 | Parent-Child Segment | 由「父分段（大块上下文）+ 子分段（小块检索）」组成的检索结构 | — |
| 清洗 | Cleaning | 对原始文本做规范化、去噪、结构化处理 | 预处理（仅限泛指） |
| 索引 | Index | 支撑检索的数据结构（向量索引 / 倒排索引） | — |
| 嵌入向量 | Embedding | 文本经 Embedding 模型生成的稠密向量 | 向量、表征（统一用「嵌入向量」） |
| 检索 | Retrieval | 依据查询返回相关分段的动作 | 搜索（仅限口语） |
| 重排 | Rerank | 对初检结果用交叉编码器/重排模型重新排序 | 精排（仅在引用 Dify 时保留） |
| 技能 | Skill | 封装「提问分析 + 知识库检索」、供大模型自主调用的工具 | 工具（Tool）、插件（混用易歧义，统一用「技能」） |
| 摄取管道 | Ingestion Pipeline | 文档从上传到完成索引的异步处理链路 | 入库流程 |

## 3. 总体架构

### 3.1 模块划分

```
┌──────────────────────────────────────────────────────────────────────┐
│                          接入层 (API / SDK)                              │
└───────────────┬───────────────────────────────┬──────────────────────┘
                │ 上传/管理                       │ 检索/问答
                ▼                                ▼
┌───────────────────────┐         ┌────────────────────────────────────┐
│  文档管理 (Document)   │         │   检索编排 (Retrieval Orchestrator)  │
│  - 元数据              │         │   - 模式路由                         │
│  - 存储分阶段标记       │         │   - 融合/重排                        │
└───────────┬───────────┘         └──────────────┬─────────────────────┘
            │                                     │
            ▼                                     ▼
┌───────────────────────┐         ┌────────────────────────────────────┐
│  摄取管道 (Ingestion)   │         │   索引层 (Index)                     │
│  - 解析/转写           │         │   - 倒排索引(全文)                    │
│  - 分段策略匹配         │         │   - 向量索引(语义)                    │
│  - 清洗                 │         │   - 混合检索引擎                     │
│  - Embedding 写入       │         └──────────────┬─────────────────────┘
└───────────┬───────────┘                         │
            │                                     ▼
            ▼                         ┌────────────────────────────────────┐
┌───────────────────────┐             │   模型层 (Model)                    │
│  存储层 (Storage)       │             │   - Embedding 模型(可配置)          │
│  - 对象存储(原文件)     │             │   - Rerank 模型(可选)               │
│  - 关系库(元数据/分段)  │             │   - ASR/VLM(Phase 2)               │
│  - 向量库(嵌入向量)     │             └────────────────────────────────────┘
└───────────────────────┘
```

### 3.2 核心模块职责

| 模块 | 职责 | 关键依赖 |
| --- | --- | --- |
| 文档管理 | 文档 CRUD、分阶段标记、状态机 | 存储层 |
| 摄取管道 | 格式解析、分段策略匹配、清洗、Embedding 写入 | 模型层、存储层 |
| 检索编排 | 模式路由、结果融合、重排、阈值过滤 | 索引层、模型层 |
| 索引层 | 维护倒排索引与向量索引，提供查询 | 向量库、全文检索引擎 |
| 模型层 | 提供可配置 Embedding / Rerank / ASR / VLM | 外部模型供应商 |
| 技能网关 | 暴露 Skill 给大模型，执行提问分析与检索 | 检索编排 |

### 3.3 数据流概要

1. **摄取流**：上传 → 解析 →（Phase 2 转写）→ 分段策略匹配 → 清洗 → Embedding → 写入索引。
2. **检索流**：查询 →（技能内）提问分析 → 模式路由 → 索引查询 → 融合/重排 → 返回分段。
3. **问答流**：大模型判定调用技能 → 取回分段 → 引用来源合成答案。

## 4. 核心概念模型

| 概念 | 属性要点 | 与 Dify 对应关系 |
| --- | --- | --- |
| 知识库 KB | 索引类型（经济型/高质量）、默认检索模式、Embedding 模型绑定 | Dataset |
| 文档 Document | 文件类型、存储阶段（P1/P2）、解析状态、分段数 | Document |
| 分段 Segment | 文本内容、位置、父分段 ID、嵌入向量、清洗后全文、元数据 | Node / Child Chunk |
| 索引 Index | 倒排索引（全文）、向量索引（语义），可独立存在 | Index Technique |
| 检索 Retrieval | 模式（keyword/semantic/hybrid）、top_k、阈值、重排开关 | Retrieval Config |

> **说明**：本系统不强制「经济型 / 高质量」二分，而是以「该 KB 是否建立了向量索引」决定可用检索模式（见 5.4）。这是对 Dify 模型的简化与统一，避免概念冗余。

## 5. 核心功能设计

### 5.1 分阶段存储

#### 5.1.1 设计目标

统一管理异构文档，按内容模态分阶段支持；当前阶段聚焦**文本与图文混排**，后续阶段通过**可插拔的格式适配器（Format Adapter）**扩展音视频与特殊格式，无需改动核心索引与检索链路。

#### 5.1.2 第一阶段（Phase 1）：文本与图文混排

**支持的文件类型**

| 类别 | 格式 | 处理说明 |
| --- | --- | --- |
| 纯文本 | `.txt` `.md` `.csv`（按文本） | 直接读取文本 |
| 版式文档 | `.pdf` `.docx` `.doc` | 抽取文本流；保留页码/章节位置 |
| 图文混排 | 上述格式中含图片 | 抽取图片为独立资产，附 OCR/VLM 描述，关联到所在分段 |

**图文混排的预期行为（MUST）**

- 图片从文档中抽取后存入对象存储，生成 `asset_id`；
- 图片所在分段记录 `asset_refs`；系统对图片做 **OCR 文本抽取**（必要时用 VLM 生成图像描述），作为该分段的补充全文参与索引；
- 检索返回时，若分段含图片，应在来源中标注图片引用，便于前端展示；
- 当 VLM 不可用，**必须降级为 OCR 文本**，不得因缺图描述而丢弃该分段。

#### 5.1.3 第二阶段（Phase 2）：音频、视频与特殊格式

通过 **Format Adapter 插件机制**接入，适配器实现统一接口：

```text
FormatAdapter:
  accept(file_type) -> bool
  extract(document) -> { text: str, assets: [Asset], segments_hint: [...] }
```

| 模态 | 适配器 | 转写/提取方式 | 产物 |
| --- | --- | --- | --- |
| 音频 `.mp3/.wav/.m4a` | AudioAdapter | ASR 转写 + 时间戳切片 | 文本分段 + 时间戳元数据 |
| 视频 `.mp4/.mov` | VideoAdapter | 关键帧抽取(VLM) + 音轨 ASR | 文本分段 + 帧资产 + 时间码 |
| 特殊格式（需特定应用打开） | AppFormatAdapter | 调用对应应用导出/转换（如 CAD→PDF、PSD→图、XMind→大纲） | 文本/图片资产 |

**Phase 2 约束（SHOULD）**

- 适配器执行在**隔离沙箱**中，超时与失败不影响其他文档；
- 转写结果为文本后，复用 Phase 1 的分段/清洗/索引链路；
- 特殊格式适配器以「先转标准格式，再走通用链路」为原则，禁止为每种格式单独造索引。

#### 5.1.4 存储模型与格式约定

| 存储对象 | 位置 | 格式约定 |
| --- | --- | --- |
| 原文件 | 对象存储（如 S3/MinIO） | 保留原始扩展名，路径 `kb/{kb_id}/doc/{doc_id}/origin` |
| 抽取图片/帧 | 对象存储 | `.../assets/{asset_id}.png`，附 `asset_meta` |
| 文本与分段 | 关系库 + 向量库 | 见第 6 节 |
| 转写稿（Phase 2） | 关系库 | JSON，含时间戳 |

#### 5.1.5 需求边界与预期行为

| 项 | 边界 |
| --- | --- |
| 支持 | Phase 1：文本、图文混排；Phase 2（架构预留）：音频、视频、特殊格式 |
| 不支持 | 实时流媒体摄取、跨 KB 去重合并、文档级权限继承（本期不做，见第 9 节） |
| 预期行为-上传 | 返回 `doc_id` 与 `status=processing`；非法格式返回 400 并列出支持列表 |
| 预期行为-失败 | 单文档解析失败仅该文档 `status=failed`，不影响 KB 其余文档 |
| 预期行为-重建 | 提供「按文档重建索引」接口，清除旧分段后重跑摄取管道 |

### 5.2 分段与清洗

#### 5.2.1 总体策略：按文档类型自动匹配

系统**必须**依据「文件类型 + 内容结构探测」自动选择分段方案，同时**应该**允许用户手动覆盖。匹配优先级：内容结构探测 > 文件扩展名 > 默认方案。

#### 5.2.2 四种分段方案

| 编号 | 方案名称 | 适用文档 | 分段逻辑 | 关键参数 |
| --- | --- | --- | --- | --- |
| **S1** | 通用规则分段 | 无明确结构的纯文本、长文档 | 按分隔符（换行/标点/空行）切分，控制最大长度与重叠 | `max_tokens=500`、`overlap=50`、`separators` |
| **S2** | 结构感知分段 | 含标题层级的 `.md/.docx`、带目录的 `.pdf` | 依标题/章节层级切分，保留层级元数据（h1/h2…） | `heading_levels`、`min_section_len` |
| **S3** | 父子分段 | 报告、手册、长 PDF | 父分段为大块（章节/1000–2000 token），子分段为小块（200–300 token）；检索子分段，返回父分段上下文 | `parent_size`、`child_size`、`child_overlap` |
| **S4** | 问答对分段 | FAQ、帮助中心、显式 Q&A 文档 | 识别「问—答」配对，每对作为一个分段；问句建索引，答句作返回 | `qa_delimiter`、`question_regex` |

**自动匹配映射（默认）**

| 文件/内容特征 | 默认方案 |
| --- | --- |
| 检测到显式问答结构 | S4 |
| 检测到多级标题且篇幅长 | S3（父子） |
| 检测到标题层级 | S2 |
| 其余 / 纯文本 | S1 |

> 说明：S3 与 S2 可组合——S2 先按结构切分，S3 再对长章节做父子化。实现上 S3 优先于 S2。

#### 5.2.3 公共清洗规则

以下清洗**必须**在所有方案执行前/中统一应用：

1. Unicode 归一化（NFKC）、去除零宽字符与控制符；
2. 折叠连续空白与空行，修复断行（hyphenation）；
3. 去除页眉/页脚/页码噪声（基于规则或版式检测）；
4. 去除重复连续段落（near-dup 去重）；
5. 剥离残留 HTML/Markdown 标记噪声，保留语义文本；
6. 修复乱码（mojibake）探测与替换；
7. 图文混排：图片以 OCR/VLM 文本并入分段全文。

**清洗边界**：清洗**不得**改写语义、不得删除表格数值、不得对正文做摘要式压缩（摘要属 Phase 2 可选能力，非默认）。

#### 5.2.4 需求边界与预期行为

| 项 | 边界 |
| --- | --- |
| 支持 | S1–S4 四种方案；自动匹配 + 手动覆盖 |
| 不支持 | 自动生成摘要作为分段（默认关闭）、跨文档语义合并分段 |
| 预期行为-自动匹配 | 返回所选方案及置信度；用户覆盖后以此为准 |
| 预期行为-超长分段 | 超过 `max_tokens` 且无自然分隔点时，强制按长度截断并在元数据中标记 `truncated=true` |
| 预期行为-空文档 | 解析后无文本 → `status=empty`，不建索引，返回提示 |

### 5.3 模型配置

#### 5.3.1 Embedding 模型配置

系统**必须**支持用户自定义 Embedding 模型，配置项如下：

| 配置项 | 含义 | 约束 |
| --- | --- | --- |
| `provider` | 供应商（OpenAI / 本地 / 自建） | 枚举 |
| `model_name` | 模型标识 | 非空 |
| `endpoint` | 推理地址（兼容 `/v1/embeddings`） | URL |
| `api_key_ref` | 密钥引用（存密钥管理，不落明文字段） | 加密存储 |
| `dimensions` | 输出向量维度 | 整数，需与库一致 |
| `batch_size` | 批量嵌入条数 | 默认 32，可调 |
| `normalize` | 是否归一化（ cosine 友好） | 默认 true |

#### 5.3.2 Rerank 模型配置（可选）

| 配置项 | 含义 |
| --- | --- |
| `rerank_provider` / `rerank_model` | 重排模型标识 |
| `rerank_endpoint` / `rerank_api_key_ref` | 重排服务地址与密钥 |
| `rerank_top_n` | 重排后保留条数，默认 10 |

#### 5.3.3 校验与约束（MUST）

- **维度一致性**：同一 KB 的所有分段嵌入向量维度**必须**与 `dimensions` 一致；更换模型后**必须**触发全量重建索引，否则拒绝写入并告警。
- **连通性探测**：保存配置时**必须**发起一次探针请求（样例文本 → 向量），失败则拒绝保存。
- **密钥安全**：密钥仅存于密钥管理，接口返回时脱敏（`sk-****`）。
- **降级**：重排模型不可用时，混合检索**必须**回退到分数融合排序，并在响应中标记 `rerank_applied=false`。

#### 5.3.4 需求边界

| 项 | 边界 |
| --- | --- |
| 支持 | 自定义 Embedding（多供应商）、可选 Rerank |
| 不支持 | 运行时自动选型、按分段动态切换模型（本期固定到 KB 级） |
| 预期行为-换模型 | 标记 KB 为 `need_reindex`，提供一键重建；重建完成前旧索引仍可用 |

### 5.4 检索模式

#### 5.4.1 三种模式定义

| 模式 | 英文 | 机制 | 适用场景 | 依赖索引 |
| --- | --- | --- | --- | --- |
| 关键字全文检索 | keyword / full-text | 倒排索引 + BM25 | 专有名词、编号、精确术语、法律/规格条文 | 倒排索引 |
| 语义检索 | semantic / vector | 嵌入向量 + 近似近邻（HNSW，cosine） | 同义改写、意图匹配、自然语言问句 | 向量索引 |
| 混合检索 | hybrid | 二者并行 + 融合 +（可选）重排 | 兼顾精确与语义，默认推荐 | 倒排 + 向量 |

**分词约束（MUST）**：中文**必须**使用分词器（jieba / IK 类），英文按空白与词形归一化；未配置分词器时 keyword 模式报错。

#### 5.4.2 混合检索融合策略

1. 并行执行语义检索与全文检索，各取 `top_k`（默认 5）；
2. 分数归一化到 [0,1]；
3. 融合（默认 **RRF 倒数排名融合**，可选加权求和 `α·sem + (1−α)·kw`）；
4. 若开启重排，对融合后 `rerank_top_n` 条用重排模型重排；
5. 按 `score_threshold` 过滤，输出最终结果。

> **RRF 公式**：`score(d) = Σ_{r∈{sem,kw}} 1 / (k + rank_r(d))`，`k=60`。

#### 5.4.3 检索接口与参数

```json
{
  "query": "如何重置管理员密码？",
  "knowledge_base_ids": ["kb_001"],
  "retrieval_mode": "hybrid",
  "top_k": 5,
  "score_threshold": 0.3,
  "rerank": true
}
```

返回：

```json
{
  "segments": [
    {
      "segment_id": "seg_xxx",
      "content": "管理员可在设置页...",
      "score": 0.82,
      "source": { "doc_id": "doc_01", "doc_name": "运维手册.pdf", "position": 12 },
      "asset_refs": []
    }
  ],
  "total": 3,
  "rerank_applied": true
}
```

#### 5.4.4 需求边界与预期行为

| 项 | 边界 |
| --- | --- |
| 支持 | keyword / semantic / hybrid 三模式；RRF 融合；可选重排；阈值过滤 |
| 不支持 | 跨语言混合检索（单查询单语言）、多轮对话记忆检索（由技能层处理） |
| 预期行为-空库 | 返回空列表 `segments=[]`，`total=0`，HTTP 200，不报错 |
| 预期行为-空查询 | 400，提示 query 必填 |
| 预期行为-缺索引降级 | semantic 无向量索引 → 若模式为 semantic 报错；hybrid 仅全文可用时降级并 `warn=missing_vector_index` |
| 预期行为-全低于阈值 | 返回空列表，附 `reason=below_threshold` |
| 预期行为-延迟 | P95 < 800ms（不含大模型），top_k≤10 |

### 5.5 技能化（Skill）

#### 5.5.1 设计目标

将「**提问分析** + **知识库检索**」封装为单一 Skill，交由大模型通过函数调用（function calling / tool choice）**自主判断是否调用**，实现「按需检索、引用作答」。

#### 5.5.2 Skill 定义（Schema）

```json
{
  "name": "knowledge_base_search",
  "description": "当用户的问题需要依据私有知识库中的事实性信息作答时调用；返回相关文档分段及来源。不适用于闲聊、通用常识、纯推理或代码生成。",
  "parameters": {
    "query":      { "type": "string", "required": true,  "desc": "经提问分析后的检索query" },
    "knowledge_base_ids": { "type": "array", "required": false, "desc": "限定知识库，缺省为全部" },
    "retrieval_mode": { "type": "enum", "enum": ["keyword","semantic","hybrid"], "required": false, "default": "hybrid" },
    "top_k":     { "type": "integer", "required": false, "default": 5 },
    "rerank":    { "type": "boolean", "required": false, "default": true }
  }
}
```

#### 5.5.3 提问分析子流程（封装在技能内）

在执行检索前，技能**应该**执行轻量提问分析：

1. **语言/实体识别**：识别查询语言与关键实体；
2. **查询改写/扩展**：对口语化、指代不明的问句做规范化（如「它」→ 前文实体）；
3. **多跳分解**：将复合问题拆为多个子查询，分别检索后合并；
4. **知识库路由**：依据实体/关键词将查询映射到最相关 KB（当未显式指定时）。

> 提问分析**不得**改变用户原意，仅做检索友好化；分析日志随检索日志留存。

#### 5.5.4 大模型自主调用决策逻辑

| 判定 | 调用技能 | 示例 |
| --- | --- | --- |
| 需要私有事实 | **调用** | “我们的退款政策是什么”“根据手册第 3 章…” |
| 实体/编号 lookup | **调用** | “订单 A2026 的状态” |
| 闲聊 / 通用常识 | 不调用 | “你好”“地球有多大” |
| 纯推理 / 代码 / 数学 | 不调用 | “用 Python 写快排” |
| 模型已确定知晓 | 不调用 | 训练知识内可答且无关私有数据 |

**实现方式（MUST）**：通过 function calling 暴露技能描述；系统提示词给出决策示例（few-shot）；模型输出工具调用即触发检索。提供**强制开关** `force_retrieve` / `force_skip` 供确定性流水线覆盖模型决策。

#### 5.5.5 预期行为与边界

| 项 | 边界 |
| --- | --- |
| 支持 | 模型自主调用；提问分析；来源返回；强制覆盖开关 |
| 不支持 | 技能写库/改 KB、技能访问外部互联网、技能直接生成最终答案 |
| 预期行为-调用 | 检索返回分段 → 模型引用 `source` 合成答案，必须标注来源 |
| 预期行为-无相关 | 分段为空时，模型**必须**明确告知「知识库中未找到相关信息」，禁止编造 |
| 预期行为-鉴权 | 技能仅能访问调用方被授权的 KB 列表 |
| 预期行为-成本 | 每次技能调用 = 1 次检索；多跳分解产生的子查询可多次检索，需设上限（默认 ≤ 4） |

## 7. 关键处理流程

### 7.1 文档摄取流程

```
上传 → 格式识别 → [Phase2: 适配器转写] → 分段策略匹配
     → 公共清洗 → 生成分段(含父子/hash) → Embedding 写入
     → 倒排+向量索引更新 → status=ready
```
- 任一非致命步失败 → `status=failed` + 错误码；支持重试。
- 同 `hash` 分段 → 去重，不重复写向量。

### 7.2 检索流程

```
query → [技能内提问分析] → 模式路由
      → keyword: 倒排+BM25 / semantic: 向量ANN / hybrid: 二者并行
      → 融合(RRF) → [重排] → 阈值过滤 → 返回分段
```

### 7.3 技能调用流程

```
用户问 → 模型决策(是否调 knowledge_base_search)
   ├─ 不调 → 直接作答
   └─ 调 → 提问分析 → retrieval(见7.2) → 返回分段
            → 模型引用来源合成答案(标注 doc_name/position)
```

## 9. 需求边界汇总（Non-Goals）

本期**明确不做**，避免范围蔓延：

1. 文档级细粒度权限继承与多租户隔离策略（仅做 KB 级授权）；
2. 跨知识库语义去重与合并；
3. 实时流媒体摄取；
4. 检索结果自动摘要生成（默认关闭，属 Phase 2 可选）；
5. 大模型自主写库/编辑知识库（技能只读）；
6. 多语言混合单查询检索（单查询单语言）。
