## 3. 既有代码缺陷清单（本次已全部修复）

### 3.1 阻断性缺陷

**D1. FTS5 虚表索引导致全新数据库初始化失败**
`database.py` 的 `idx_kb_segments_fts_kb` 对 FTS5 虚表建普通索引，SQLite 直接报
`virtual tables may not be indexed`，`executescript` 整体中断——**任何全新库（含测试隔离库）
都无法完成建表**，后续索引语句也不会执行。修复：删除该索引（kb_id 过滤走与 `kb_segments`
的 JOIN，由 `idx_kb_segments_kb` 承担）。既有开发库已自愈（重跑 init_schema 自动补齐）。

**D2. S3 父子分段的 `parent_id` 与数据库行 id 不一致**
`chunk_s3` 用 `sha1(content_hash)` 生成 parent_id，落库时行主键却是新生成的 uuid，
库内 `kb_segments.parent_id` 永远无法 JOIN 回父段，「检索子段、返回父上下文」落空。
修复：`Segment` 增加稳定本地 `id` 字段（`_mk` 统一生成 uuid），repository.create 优先复用
`segment.id` 作为行主键，子段 `parent_id == 父段行 id`。

### 3.2 数据/语义缺陷

**D3. 清洗规则误删中文间的换行**
`clean_text` 的「CJK 间空格折叠」用了 `\s+`，把 CJK 之间的换行也吃掉了，
段落结构被破坏、S1/S2 分段失效。修复：限定为 `[ \t]+`（换行是分段结构依据，绝不能动）。

**D4. `truncated` 标记逻辑失效**
`_mark_truncated` 检查「最终片长 > MAX」，而硬切后的每片都不超长，标记永远不触发。
修复：硬切产出的片段在创建时即打 `truncated=True`（方案 5.2.4 的语义是「被迫硬切」这件事）。

### 3.3 状态/授权缺陷

**D5. `build_vectors` 后 `index_type` 不升级**
写入向量后仍停留在 `fulltext`，从未变为 `both`。修复：写入成功即置 `both`。

**D6. `skill_search` 授权边界缺失**
显式传入 `knowledge_base_ids` 但无一解析成功时，`routed or None` 把空列表变成
`None`（= 全部知识库），调用方限定的范围被无声放大。修复：显式指定且无可访问 KB 时
返回空结果，不回退全库（方案 5.5.5）。

**D7. 解绑嵌入模型不标记 `need_reindex`**
`update_kb` 只在「换成新模型」时置标记，解绑（置 None）不置。修复：`embedding_model_id`
发生任何变化（含解绑）都置 `need_reindex=1`。

### 3.4 工程问题

**D8. 测试隔离不完整**：`conftest.py` 未隔离 `HARNESS_KNOWLEDGE_DIR`，上传测试会把
原文件/资产写进真实 `data/knowledge/`。已补隔离。

**D9. lint 问题一批**：`parsers.py`（3×E501、N814、I001）、`repository.py`（2×E501）、
`service.py`（2×I001、F401 未用导入）。已全部修复，现 ruff check + format 全绿。

### 3.5 第二轮（v1.1）发现与修复

**D10. 分段接口暴露 embedding 原始字节 → API 500**
`repository._decorate` 把 `embedding`（float32 bytes）原样带给上层，`GET /api/kb/{id}/segments`
在分段已建向量时 FastAPI 无法序列化 bytes（解码失败）→ 500。修复：`_decorate` 剥离
原始字节、改暴露 `has_embedding` 布尔；`build_vectors` 的「缺失判定 / 全量清空」同步
改用该布尔。已补 API 层回归测试（`test_segments_endpoint_serializes_with_embeddings`）。

**附：解析改线程执行**（非缺陷，健壮性改进）：`_process_document` 的 `parse_document`
改为 `asyncio.to_thread`——P2 网络适配器（ASR）为阻塞 IO，且大 PDF/DOCX 解析不再阻塞事件循环。


### 6.4 配置嵌入模型后启用语义检索

1. `POST /api/kb/embedding-models`（或先用 `/probe` 测试连接）——保存前自动探针，
   维度以探针实际值回填；密钥加密存储、接口脱敏返回；
2. `PUT /api/kb/{kb_id}/embedding-model` 绑定模型（自动置 `need_reindex`）；
3. `POST /api/kb/{kb_id}/reindex` 全量重建向量 → `index_type=both`，
   `semantic`/`hybrid` 的向量通路随之生效。

### 6.5 图片描述（图文混排）

环境无 OCR 库；配置 `HARNESS_KB_VLM="provider_id:model"` 后，上传时调用已配置
Provider 的 OpenAI 兼容视觉接口生成描述；不可用降级为占位文案，图片仍以独立资产分段参与检索。

### 6.6 音频转写（P2，v1.1）

```bash
# backend/.env.local（或系统环境变量）
HARNESS_KB_ASR_ENDPOINT=http://127.0.0.1:9000/v1   # 可给 base 或完整 /audio/transcriptions
HARNESS_KB_ASR_API_KEY=                            # 本地服务可省略
HARNESS_KB_ASR_MODEL=whisper-1                     # 默认 whisper-1
```

配置后直接上传 `.mp3 / .wav / .m4a / .flac / .ogg / .aac` 即可（转写文本进入标准
分段/清洗/索引链路）；未配置时上传音频返回明确指引（`KB_PARSE_FAILED`，仅该文档失败）。
